2. 仕組み
--------------------------------------------------------------------------
 ■ GPU のバッファ (容量は 2 の累乗。既定 2^18 = 262,144 個で約 21MB)
   Particles [容量] 64byte / DeadList [容量] uint / AliveList [2][容量] uint2 (キー, 番号) / Counters / Args / Emitters [1024] 160byte
 ■ 毎フレーム (命令 UpdateParticles)
   エミッターを UPLOAD → VRAM へ写す → Begin (1 スレッド : 出す数 = min(頼んだ数, 空き)、更新の Dispatch の引数)
   → Emit (頼んだ数のスレッド。SpawnOffset を二分探索してエミッターを決める。空きリストの決まった場所を使うので Atomic 無し)
   → Simulate (DispatchIndirect。重力 / 乱れ / 空気抵抗 / 衝突 / 色と大きさ。生き残りは出力の列、死んだ物は空きリストへ。
      どちらも Wave ごとに 1 回の Atomic : WaveActiveCountBits + WavePrefixCountBits)
   → Finish (1 スレッド : DrawInstanced(6, 生存数) の引数) → (ソート) → 数を読み戻す (2 フレーム後に CPU が読む)
 ■ 描画 (命令 DrawParticles) : ExecuteIndirect 1 回 (全エミッター・全パーティクル)。
   ルートシグネチャはシーンと同じ物のまま、頂点シェーダーのルート SRV t1 / t2 を描く間だけパーティクル / 生存リストに差し替えて戻す
   (ルートシグネチャを変えないので、既存の PSO は作り直しにならない)
 ■ C# : ParticleSystem がエミッターごとに「このフレームに出す数」(Rate × dt の端数を持ち越す + Burst) を決め、
        全エミッターを 1 回の P/Invoke で送る。エミッターの番号は、外した後も寿命の最大 + 0.25 秒は使い回さない (資料 p.87)

4. デバッグレイヤーで出たエラーと直し方
--------------------------------------------------------------------------
 - 「DATA_STATIC_WHILE_SET_AT_EXECUTE で結ばれたリソースが書ける状態に変わった。結び直すこと」が、更新の後の描画ごとに出た
   原因 : パーティクルのコンピュートのルートシグネチャの「シーンの深度」のテーブルを DATA_STATIC にしていた。
          更新の後に深度は描画先 (DEPTH_WRITE) に戻るが、コンピュートのルート引数は次のコンピュートまで結ばれたまま残る
   直し : そのテーブルを DATA_VOLATILE に (STATIC に戻すと再発、VOLATILE だけで 0 になることを確認)
 - (確認の手順の注意) RHI だけ作り直しても C# の出力フォルダの RHI.dll は古いまま (C# のビルドで写る)。毎回 C# も作り直すこと
