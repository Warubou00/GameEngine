====================================================================
 最適化 : 裏面カリング (+ PSO キャッシュの名前の修正)
 日付   : 2026-11-02
 ブランチ : feature/backface-culling (develop bcc73c1 から)
====================================================================

■ 概要
  - 不透明な物の裏面を描かないようにした (以前はシーンの全部を両面で描いていた。Pipeline.cpp の TODO だった所)
  - 両面のマテリアル (MaterialDesc.DoubleSided。PMX の材質の「両面描画」フラグ) は、裏面カリングをしない PSO で描く
  - 半透明は描く順番 (PMX の材質の順) を崩せないので、今までどおり両面で描く
  - 見本のシーンで GPU 時間 -0.04 ms (約 16%)。見た目は変わらない
  - ついでに見つけた PSO キャッシュの不具合を直した (下の「PSO キャッシュ」)

■ 仕組み
  描き方のまとまり (PSO) を 2 つから 3 つにした
      0 : 不透明 (片面。裏面カリング)       ← 以前の「不透明」
      2 : 不透明 (両面。カリングしない)     ← 新規
      1 : 半透明 (両面)                     ← 以前と同じ
    番号の 0 / 1 は RHI::BlendMode と同じまま。引数の並びは 不透明 → 両面の不透明 → 半透明
    (半透明を最後に置き、GPU カリングの「半透明の先頭より後ろ = 半透明」の見分け方を変えないようにした)
  GPU カリング (gpuCulling.shader)
    - 詰め直し (CSCompact) のカウンターを 3 つにし、両面の不透明の先頭 (g_DoubleSidedDrawStart) で見分ける
      (各まとまりの先頭は 64 の倍数にそろえるので、64 個ずつの処理の中で描き方は混ざらない)
    - ルート定数 33 → 34 個 (上限 64 DWORD の中 : 54)
    - 2 段階のオクルージョンの前段も、片面 → 両面の順に 2 回の ExecuteIndirect で描く
  面の向き
    - 画面上で時計回りが表 (D3D の既定。FrontCounterClockwise = FALSE)
      以前は TRUE だったが、カリングしていなかったので意味が無かった
    - OBJ (箱 / 岩 / 地面) と PMX (トミミ) の両方で、裏面を消しても正しく表示されることを確かめた
      (PMX は半透明なので普段はカリングしない。確かめるために一時的にカリングして撮った)
  データ
    - RHI::MaterialDesc に DoubleSided (既定 false) を追加。Renderer は Material::DoubleSided をそのまま渡す
    - Buffer は CPU 側にだけ持つ (GPU のマテリアルのデータ 32 byte は変えない)

■ PSO キャッシュ (pipeline.cache) の修正
  - キャッシュの名前 (ハッシュ) にラスタライザーの設定が入っていなかった
    裏面カリングを入れると、前の両面の PSO と同じ名前になり、Debug で
      "ID3D12PipelineLibrary::Load*Pipeline: The pipeline state desc provided does not match ..."
      "[PipelineCache] StorePipeline failed"
    が出ていた (毎回作り直しになり、キャッシュが効かない)
  - RasterizerState もハッシュに入れた。名前が全部変わるので、初回の起動だけ PSO を作り直す
    (古い名前の分は pipeline.cache に残る。気になる時は pipeline.cache を消せば作り直される)

■ 計測
  RTX 2070 / Release / 1280x720 / GPU 時間 (ms)。2 回計測して ±0.003 以内
                                          以前     今      差
    見本 / SSAO なし                      0.239   0.201   -0.038 (-16%)
    見本 / SSAO (既定 = FXAA なし)        0.335   0.297   -0.038
    見本 / SSAO + FXAA (既定の設定)       0.396   0.358   -0.038
    見本 / SSAO + MSAA 4x                 0.492   0.447   -0.045
    見本 / Deferred + SSAO                0.333   0.307   -0.026
    負荷テスト 20002 個 / SSAO なし       0.266   0.250   -0.016
    負荷テスト 20002 個 / SSAO            0.338   0.322   -0.016
  (以前の値は E3 のアンチエイリアスのログと、最適化の検討の時に測った物。同じ PC・同じ手順)
  Deferred の差が小さいのは、G-Buffer のピクセルシェーダーが軽く (ライティングは全画面で 1 回)、
  裏面のピクセルを減らした効果が小さいため
  負荷テストの差が小さいのは、箱が多くて小さく、頂点の処理の割合が大きいため (裏面カリングは頂点の処理は減らさない)

■ 確認
  - Debug (D3D12 デバッグレイヤー有効) で D3D12 のエラー / 警告 0 (PSO キャッシュの修正の後)
      Forward / Deferred / FXAA / MSAA 4x、負荷テスト (ground / inside)、リサイズ、F2〜F6 の切り替え
      2 回目の起動で PSO をキャッシュから読むことも確認
  - 両面の不透明のまとまりの確認 : 見本のシーンには両面の不透明なマテリアルが無いので、
    一時的に「マテリアルを 1 つおきに両面」にして、3 つのまとまりが混ざった状態で
    描画数・映った数 (34 / 45、負荷テスト 252 / 1010) と見た目が変わらないこと、エラー 0 を確かめた (確認後に戻した)

■ 制限 / 次
  - 半透明は両面のまま (PMX の片面の材質も裏面を描く)。材質ごとに PSO を切り替えると描画をまとめられなくなる
  - 次の候補 (最適化の検討より) : Forward + SSAO の「環境光 × 遮蔽」をトーンマップに入れる (-0.03 ms が上限)、
    MSAA の深度の解決を 1 フレーム 1 回にする
