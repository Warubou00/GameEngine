====================================================================
 描画ごとのルート引数をなくす (DrawID 方式) : ExecuteIndirect の GPU 時間の改善
 日付   : 2026-11-02
 ブランチ : feature/indirect-gpu
 調査   : ClaudLog/ExecuteIndirect_GPU_Investigation_2026-11-02.txt
====================================================================

■ 目的
  Phase 4 の ExecuteIndirect は CPU を大きく軽くしたが、GPU 時間は direct より増えていた
  (Release 20002 描画 : direct 0.54 ms / indirect 0.84 ms)。
  調査の結果、GPU が描画ごとにルート引数 (ルート定数 b0 / ルート CBV b2) を書き換えるのが原因と分かった。
  描画ごとのルート引数をなくし、シェーダーが「何番目の描画か (DRAWID)」でデータを引く形に変えた。

■ 仕組み
  1. 描画番号バッファ (0, 1, 2, ... 65535 の uint。VRAM に初期化時 1 回だけ転送)
     → 入力レイアウト DRAWID (インスタンス単位、R32_UINT) として 1 回だけ設定する。
       各描画は StartInstanceLocation = 描画番号 で描くので、シェーダーにその番号が届く。
       (SV_InstanceID には StartInstanceLocation が加算されないため、入力アセンブラに読ませる)
  2. DrawData { ObjectIndex, BaseVertex } (8 byte) を描画ごとに用意し、Root SRV (t1) で読む。
     ExecuteIndirect の引数と同じバッファ (フレームごと、UPLOAD → VRAM コピー) に置き、
     描画リストが変わった時だけ書き直す。
  3. オブジェクトのデータは Root SRV (t2, StructuredBuffer<ObjectData>) としてフレームの領域の先頭を
     1 回だけ設定し、DrawData.ObjectIndex で引く。テクスチャ番号は nointerpolation でピクセルシェーダーへ渡す。
  4. ExecuteIndirect のコマンドシグネチャは DrawIndexed だけ (40 byte → 20 byte、ルートシグネチャ無し)。
  5. direct (1 個ずつ描く) も同じ仕組みにした。描画ごとの API 呼び出しは DrawIndexedInstanced だけになり、
     引数は CPU 側の控え (UPLOAD ヒープは CPU から読むと遅いので読まない) から取る。

■ 計測結果 (RTX 2070 / 1280x720 / --stress 10000 = 20002 描画)
                        変更前                              変更後
                        FPS    記録(CPU)   GPU              FPS    記録(CPU)   GPU
    Release indirect   700    0.050 ms    0.84 ms          921〜947  0.045 ms   0.27 ms
    Release direct     654    0.468 ms    0.61 ms (*)      846〜855  0.23〜0.26 ms 0.28 ms
    Debug   indirect   601    0.065 ms    0.86 ms          836    0.063 ms    0.24 ms
    Debug   direct     13.3   72.4 ms     2.30 ms          17.9   53.9 ms     1.71 ms
    (*) 同じ日の別の計測では 0.54 ms

  - ExecuteIndirect の GPU 時間は 約 1/3 (0.84 → 0.27 ms)。direct より遅かったのが、同じかわずかに速いところまで来た。
  - direct も GPU が半分、CPU の記録が半分になった (描画ごとのルート引数の設定が無くなったため)。
  - 実験の「描画だけ (0.43 ms)」より速いのは、実験ではルート引数が未設定で正しく描けていなかったため
    (重なった描画が多かったと考えられる)。今回は画面で正しく描けていることを確認した。
  - D3D12 デバッグレイヤーのエラー・警告なし。

■ 確認したこと
  - 通常起動 : 箱がこれまでどおりテクスチャ付きで描画される。
  - --stress 10000 : ExecuteIndirect / direct のどちらでも同じ格子状の描画になる。
  - シェーダーと PSO のキャッシュは自動で作り直された (ハッシュが変わるため)。2 回目以降はキャッシュから読む。

■ 変更点の詳細
  hlslTemplate.shader
    - cbuffer MeshInfo (b0) と cbuffer ObjectData (b2) を削除。
    - StructuredBuffer<DrawData> g_Draws (t1) / StructuredBuffer<ObjectData> g_Objects (t2) を追加。
    - GlobalData は b1 → b0。テクスチャ配列は t1 → t0, space1 (上限の無い範囲なので空間を分けた)。
    - VSMain に入力 DRAWID を追加。TextureID を nointerpolation で PS へ渡す。
  Pipeline.h / Pipeline.cpp
    - ルートパラメータ : [0] 頂点バッファ表 t0 / [1] Global CBV b0 / [2] DrawData SRV t1 /
                         [3] ObjectData SRV t2 / [4] テクスチャ表 (t0, space1)。
    - ルートシグネチャに ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT を追加 (入力レイアウトを使うため)。
    - Global CBV は頂点シェーダーだけで使うので VERTEX のみに。
    - 入力レイアウト DRAWID を追加。コマンドシグネチャは DrawIndexed のみ・ルートシグネチャ無し。
  dx12_commandSignature.h
    - IndirectDrawCommand = D3D12_DRAW_INDEXED_ARGUMENTS だけ (20 byte)。
  Buffer.h / Buffer.cpp
    - オブジェクトの間隔 SCENE_CB_STRIDE (256 byte) → OBJECT_DATA_STRIDE (80 byte)。
      Root CBV で指さなくなったので 256 境界は不要。1 フレームに置けるオブジェクトは 32768 → 104857。
  CommandContext.h / CommandContext.cpp
    - IndirectFrame → DrawFrame (DrawData と引数を同じバッファに置く : [DrawData × 65536][引数 × 65536])。
    - updateDraws : 描画リストが変わった時だけ DrawData と引数を書き、VRAM へコピーしてバリア
      (COPY_DEST → NON_PIXEL_SHADER_RESOURCE | INDIRECT_ARGUMENT)。同じなら何もしない。
    - 描画番号バッファを作成し、RenderStart で IASetVertexBuffers (ImGui が差し替えるので毎フレーム)。
    - renderIndirect と、direct の描画ごとのルート引数の設定を削除。

■ 注意 (挙動の変化)
  - 1 フレームの描画数の上限は 65536 (MAX_DRAWS)。超えた分は描かれず、ログに 1 回だけ警告を出す。
    (以前は ExecuteIndirect が 32768 までで、超えた分は 1 個ずつ描いていた)
  - DrawData を使うため、Render は 1 フレームに 1 回だけ呼ぶこと (今の RHI はそうなっている)。

■ この先の案 (今回は見送り)
  - インスタンシング (同じメッシュをまとめて 1 描画に)、GPU カリング (コンピュートで引数を作る)。
  - Shader Model 6.8 (Agility SDK) の SV_StartInstanceLocation : 描画番号バッファが不要になる。
