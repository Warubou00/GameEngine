====================================================================
 エンジン化 E3 (3/3) : アンチエイリアス (FXAA / MSAA)
 日付   : 2026-11-02
 ブランチ : feature/e3-aa
====================================================================

■ 概要
  - FXAA (ポストエフェクト) と MSAA (固定機能 = ハードウェア) を追加。実行中に切り替えられる (F6)
      なし → FXAA → MSAA 2x → 4x → 8x → なし ...
      コマンドライン : --aa none|fxaa|msaa2|msaa4|msaa8
      C# : Graphics.AntiAliasing (既定 FXAA) / Graphics.Fxaa (強さ・しきい値) / Graphics.MaxMsaaSamples
  - MSAA は Forward だけ。Deferred で MSAA を選ぶと代わりに FXAA を掛ける
    (プロファイラーの "Render pipeline" に "FXAA (MSAA not available)" と出る)
  - GPU が対応していないサンプル数は、対応している一番大きい数に下げる (C++ が起動時に調べる)

■ 仕組み
  FXAA (antiAliasing.shader の PSFxaa)
    - トーンマップの結果を一度 RGBA8 に描き (アルファに明るさ)、FXAA でバックバッファへ
      トーンマップの後に掛ける : 明るさが画面の見た目と同じになる (HDR のままだと明るい所の小さな差を縁と見なす)
    - 1. 上下左右とのコントラストが小さい所は何もしない
      2. 縁の向き (横 / 縦) と向こう側を決める
      3. 縁に沿って両側へ縁の端まで探す (最大 10 歩。近くは 1 ピクセルずつ、遠くは大きく)
      4. 端までの距離から、縁を横切る方向にずらして線形補間で読む
      5. 1 ピクセルの細い物はサブピクセルとしてぼかす
    - 明るさは GatherAlpha で 2x2 をまとめて読む (縁でない所は 2 回の読み込みで終わる)

  MSAA (RHI の CommandContext)
    - C# からは「サンプル数を指定した RenderTexture」(RenderTexture.Create(..., sampleCount)) に見える
    - 解決 (Resolve) は RHI が自動で行う : 描画先にした後、全画面のシェーダーで読む時に 1 サンプルの写しへ
      ResolveSubresource する (C# は解決を意識しなくてよい。1 フレームで読む前に 1 回だけ)
    - シーンの深度 (SceneDepth) : 描画先が MSAA なら、RHI が同じサンプル数の MSAA の深度を別に持って付ける
      Hi-Z (オクルージョン) / SSAO / ディファードは 1 サンプルの深度を読むので、読む前に PSResolveDepth で解決する
        深度は平均すると物の縁でどちらの物でもない深度になるので、サンプルの「一番奥」を選ぶ
        (一番奥 : Hi-Z が縁で見えている物を隠れたと判定しないように、控えめな側に倒す)
      2 段階のオクルージョン : 前段を描いた後に解決 → Hi-Z → 後段 (MSAA の深度に描き続ける)
    - PSO はサンプル数ごとに作る (鍵にサンプル数を追加)
    - ルートシグネチャ : テクスチャの配列 (t0, space1) と同じ場所を MSAA のテクスチャ (t0, space2) としても読めるようにした
      (範囲を重ねる。深度の解決のシェーダーが Texture2DMS で読むため。ルート引数の数は変わらない)
    - Forward + SSAO : 環境光の RT も HDR と同じサンプル数にする (同時に描くため)。
      「環境光 × 遮蔽」を足すパスは MSAA の HDR に描く (縁のサンプルには平均した値が足される)

  Deferred で MSAA を使わない理由
    - G-Buffer (3 枚 + 深度) を 4x にすると 1280x720 で約 56MB、帯域も 4 倍
    - ライティングも縁のサンプルごとに行う必要がある (縁を見分けてサンプルごとに計算する仕組みが要る)
    → 性能と相談して、Deferred は FXAA にした

■ 高速化 (計測して決めたこと)
  RTX 2070 / Release / 1280x720 / GPU 時間 (ms)。見本のシーン / PBR / SSAO あり (2 回計測して同じ値)
                                   GPU     増えた分
    なし                           0.335
    FXAA                           0.396   +0.06
    MSAA 2x                        0.451   +0.12
    MSAA 4x                        0.492   +0.16
    MSAA 8x                        0.707   +0.37
    なし (SSAO なし)               0.239
    MSAA 4x (SSAO なし)            0.350   +0.11   (SSAO ありだと環境光の RT も MSAA になる分 +0.05 多い)
    Deferred なし / FXAA           0.333 / 0.393
    負荷テスト 20002 個 なし / FXAA / MSAA 4x   0.338 / 0.397 / 0.62

  1. FXAA の明るさをトーンマップがアルファに書き、GatherAlpha で読む
     以前 (最初の実装) は色を 5 回 (縁なら 9 回) 読んでから明るさを計算していた
     +0.069 → +0.061 ms。内訳 : パスを 1 つ足すだけで +0.017 / 縁かどうかの判定まで +0.035 / 縁の処理 +0.026
     見本のシーンは草のテクスチャの模様が細かく、縁と判定されるピクセルが多い (確認用に色を付けて見た)。
     探索の歩数を 10 → 5 にしても 0.005 ms しか変わらないので、品質を優先して 10 のまま
     (FXAA は模様の細かいテクスチャも少しぼかす。気になる時は Graphics.Fxaa.EdgeThreshold を上げる)
  2. MSAA の解決は読む時に 1 回だけ (描画先にしたら印を付け、全画面のシェーダーが読む時に解決する)
  3. MSAA の深度の解決は、MSAA の深度に描いた後で 1 サンプルの深度を読む時だけ
     (Hi-Z の前と、SSAO の前。SSAO が無ければ Hi-Z の前の 1 回)

■ 確認
  - Debug (D3D12 デバッグレイヤー有効) で D3D12 のエラー / 警告 0
      Forward : MSAA 2x / 4x / 8x / FXAA、SSAO あり / なし、負荷テスト (MSAA 8x)
      Deferred : FXAA / MSAA 8x を選んだ時 (FXAA になる)
      F6 で 3 周の切り替え、F2 (Forward ⇔ Deferred)・F4・F5 との組み合わせ、ウィンドウのリサイズ (MSAA 4x)
  - 拡大して比べた : 地面と空の境目 / 岩 / 箱の縁で、FXAA・MSAA とも縁が中間の色になる
      (地面と空の境目で、中間の色のピクセル : なし 0 / FXAA 111 / MSAA 2x 78 / 4x 106 / 8x 126)
  - MSAA 4x で遮蔽だけの表示 (F5) が MSAA なしと同じに出る (深度の解決が正しい)

■ 制限 / 次
  - MSAA の色の解決はハードウェアの平均 (HDR のまま)。とても明るい物 (ライトのハイライト) と暗い物の境目は
    トーンマップの後に段が残ることがある (明るさで重みを付けて解決するシェーダーにすると直る)
  - MSAA は物の縁だけに効く。テクスチャの中 / ハイライトのギザギザには効かない (FXAA は効く)
  - MSAA と FXAA の同時使用はまだできない (必要なら Graphics.AntiAliasing をフラグにする)
  - Deferred の MSAA は未対応 (上記の理由)
