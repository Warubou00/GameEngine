  bin フォルダは git 管理外なので、この内容は履歴に残っていなかった。

--------------------------------------------------------------------------------
1. hlslTemplate.shader
--------------------------------------------------------------------------------
  [1-7] 頂点レイアウトが C++ と一致していなかった
    原因: HLSL の struct Vertex が Position / Color / UV の 36byte、
          C++ の Renderer::Vertex は Position / pad / Normal / pad / Color / UV の 56byte。
          StructuredBuffer は 1要素 = C++ 側の stride(56byte) で並んでいるので、
          2頂点目以降の読み取り位置がずれていた。
    対策: HLSL 側にも padding と Normal を入れて 56byte に揃えた (オフセットをコメントで明記)。

  [2-7] 頂点シェーダーが行列を使っていなかった
    対策: ローカル → ワールド → ビュー → クリップ の順に変換するようにした。
            worldPos = mul(float4(pos, 1), g_WorldMatrix)
            viewPos  = mul(worldPos, g_ViewMatrix)
            clipPos  = mul(viewPos, g_ProjectionMatrix)
    掛け順の理由:
          C++ 側は DirectXMath (行ベクトル規約 v * M) で作った行列を XMMatrixTranspose してから送っている。
          HLSL の matrix は既定で column_major として読むので、転置済みの行列は
          シェーダー上では元の M として見える。よって mul(ベクトル, 行列) が正しい。
          (bin 側のデバッグ版でも同じ結論になっていた)

  [その他]
    - 法線をワールド空間に変換して VSOutput に渡すようにした (ライティングはまだ。今は未使用)
    - ピクセルシェーダーを「頂点カラー × テクスチャ」に戻した (bin 側はデバッグ用に固定値になっていた)
    - 文字コードは UTF-8 (BOMなし)。FXC は BOM を読めないので付けていない (ファイル先頭に注意書き)
    - 各リソースがどの RootParameterIndex に対応するかをコメントで明記


--------------------------------------------------------------------------------
2. Renderer 側
--------------------------------------------------------------------------------
  [1-7 後半] 頂点カラーが 0 (黒) だった
    原因: Vertex のメンバーに既定値が無く、OBJ ローダーも Color を設定していない。
          ピクセルシェーダーは「頂点カラー × テクスチャ」なので、常に黒になっていた。
    対策: Renderer::Vertex に既定値を付けた (Color は白、他は 0)。
          → OBJ ローダーを変更せずに白になる。テクスチャ無しなら既定テクスチャ(白) × 白 = 白。

  [サイズ検査]
    vertex.h に static_assert を追加 (sizeof == 56, Normal / Color / UV のオフセット)。
    C++ 側の Vertex を変えた時に、シェーダーとの不一致がコンパイルエラーで分かる。

  [C4099] 前方宣言の class / struct 不一致を修正
    - IModelLoader.h : class Mesh;     → struct Mesh;
    - objLoader.h    : class Material; → struct Material;
    (この 2 ファイルは ASCII の行だけ書き換えたので Shift-JIS のまま)

  [World行列] Buffer::LoadModel で World 行列も View / Projection と同じく転置して送るようにした
    (今は単位行列なので結果は同じだが、移動・回転を入れた時に正しくなるように)

3. 実行時のファイル配置 (要確認)
--------------------------------------------------------------------------------
  C# の出力フォルダ (bin/x64/Debug/net9.0-windows) にある DLL は 9/28 のまま。
  今回までの修正を動かすには、次のファイルを手動でコピーする必要がある:
      RHI/x64/Debug/RHI.dll           → bin/x64/Debug/net9.0-windows/
      Renderer/x64/Debug/Renderer.dll → bin/x64/Debug/net9.0-windows/
      Core/x64/Debug/Core.dll         → bin/x64/Debug/net9.0-windows/
      RHI/Source/Shader/hlslTemplate.shader → bin/x64/Debug/Shader/
  ※提案: C# の csproj にビルド後コピーを入れれば、ソースと実行時のファイルがずれなくなる。


  ★追記 (同日) : csproj でコピーを自動化した
    GameEngine_console.csproj に CopyNativeEngineFiles ターゲットを追加 (AfterTargets="Build")。
      - Core / Renderer / RHI の DLL (+PDB) → $(OutDir)
      - RHI/Source/Shader/*.shader          → $(OutDir)..\Shader\  (RHI が "../Shader/" から読むため)
      - C# の Debug/Release に合わせて C++ 側の x64\Debug / x64\Release を選ぶ
      - RHI.dll が無い時は警告を出す
      - ※C++ 側は自動ではビルドされない。先に GameEngine.sln (C++) をビルドすること
    → これでリポジトリの RHI/Source/Shader が正本になった。bin 側の旧シェーダー (デバッグ版) は
      上書きされたが、内容はセッションの作業領域にバックアップしてある。
