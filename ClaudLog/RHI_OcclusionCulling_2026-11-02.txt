====================================================================
 オクルージョンカリング (Hi-Z : 前のフレームの深度で、隠れている物を除く)
 日付   : 2026-11-02
 ブランチ : feature/occlusion-culling
====================================================================

■ 概要
  GPU カリング (視錐台) に、オクルージョンカリングを足した。
  シーンを描き終えた深度から Hi-Z (深度の縮小ピラミッド) を作っておき、次のフレームの CSCull で、
  視錐台の中にある物について「手前の物に完全に隠れているか」を調べて、隠れている物を描かない。
  CPU は何も待たない (すべて同じコマンドリストの中で GPU が行う)。

■ 流れ
  [フレーム N : シーンを描いた直後 (CommandContext::buildHiZ)]
    1. 深度バッファをバッファに写す (DEPTH_WRITE → COPY_SOURCE → CopyTextureRegion → DEPTH_WRITE)
       深度バッファは DENY_SHADER_RESOURCE で作ってあり、シェーダーから直接は読めない。
       バッファに写せばルート SRV で読めて、ディスクリプタヒープの管理も要らない。
    2. hiZ.shader (CSDownsample) で、2x2 の「一番奥 (値が大きい)」を取りながら半分ずつにしていく。
       段 0 = 画面の半分 (切り上げ)、最後の段 = 1x1。全段を 1 本のバッファに詰めて並べる。
    3. この時のカメラ (View × Projection) を覚えておく。
  [フレーム N+1 : 描く前 (CSCull の中、gpuCulling.shader の isOccluded)]
    4. 視錐台の中にある物の境界球を囲む立方体の 8 頂点を、フレーム N のカメラで画面に投影する
       (カメラの後ろ / 手前のクリップ面にかかる物は判定しない = 描く)。
    5. 画面上の四角形が 2x2 texel 以内に収まる段を選び、その最大 4 texel の「一番奥」を読む。
    6. 物の一番手前がそれより奥なら、その範囲の物すべての後ろにある = 隠れている → 描かない。

■ Hi-Z を作る処理の高速化 (計測して分かったこと)
  最初は 1 段ごとに Dispatch + UAV バリアにしていたが、オクルージョンカリングの固定の負担が 約 0.065 ms と大きかった。
  分解して測ると (箱 1 個のシーン) :
      深度の写し     +0.012 ms
      段 0           +0.015 ms
      段 1〜10       +0.032 ms   ← データはほとんど無いのに、Dispatch とバリアごとの GPU の待ちが積み重なる
  → 1 回の Dispatch で最大 5 段を作るようにした (16x16 スレッドのグループが自分の範囲を groupshared で 16→8→4→2→1 と縮める)。
    1280x720 で 11 回 → 3 回。固定の負担は 約 0.065 → 0.04 ms。結果は 1 段ずつ作った時と同じ。

■ 計測結果 (RTX 2070 / Release / 1280x720 / ExecuteIndirect + インスタンシング + GPU カリング、各 2 回)
                                              映った数 (GPU)     オクルージョンなし   あり
    地面すれすれ (--view ground)                14850 → 1010       0.178 ms            0.115 ms  (-35%)
    格子の中から (--view inside、隠れる物なし)    4996 → 4996       0.106 ms            0.153 ms  (+0.047)
    全体が映る (隠れる物なし)                   20002 → 20002      0.203 ms            0.247 ms  (+0.044)
    通常起動 (箱 1 個)                              2 → 2           0.038 ms            0.075 ms  (+0.037)

  正直なまとめ :
    - 手前の物で奥が隠れる場面 (建物・地形・室内など) では大きく効く (このテストで -35%、描画数は 1044 → 252)。
    - 隠れる物が無い場面では、Hi-Z を作る分 (深度の写し + 3 回の Dispatch) と判定の分で 約 0.04 ms の損。
    - 実際のゲームは隠れる物が多いことが普通なので、既定は ON にした。プロファイラー / --occlusion off で切り替えられる。
    - 前のフレームの深度を使うので、カメラが速く動くと、新しく見えた物が 1 フレーム遅れて出ることがある
      (静止したカメラでは起きない。これを無くすには「2 段階のオクルージョンカリング」が必要で、今回は見送り)。

■ 確認したこと
  - 地面すれすれのカメラで、オクルージョンカリングの ON / OFF の画面を比べ、シーンの範囲 142000 ピクセルで違いが 0
    (隠れていない物を誤って消していない)。
  - D3D12 デバッグレイヤーのエラー・警告なし (Debug、各カメラ)。
  - リサイズ時は Hi-Z を作り直し、作り直した直後のフレームはオクルージョンカリングをしない。
  - GPU カリングが OFF のフレームは Hi-Z を作らず、次にカリングする時も古い Hi-Z は使わない。

■ 変更点
  新規 : RHI/Source/Shader/hiZ.shader (CSDownsample)
  gpuCulling.shader : CullConstants に Hi-Z のカメラ・大きさ・段数 (段数 0 = オクルージョンなし)、t4 Hi-Z、isOccluded
                      ※HLSL の cbuffer は matrix を 16byte 境界に置くので、C++ 側の CullConstants に詰め物を 1 個入れた
                      ※ルートシグネチャは上限 64 DWORD に対して 63 (ルート定数 47 + ルート SRV / UAV 8 個)
  Pipeline.h/.cpp   : Hi-Z 用のルートシグネチャと PSO (makeHiZPipeline)、カリングのルートパラメータに CULL_PARAM_HIZ
  CommandContext    : createHiZ (深度バッファを作る時に一緒に作る) / buildHiZ / transitionHiZ、カリングの定数に Hi-Z を渡す
  Buffer            : GetViewProjectionForShader (視錐台と一緒に計算)
  プロファイラー    : 「Occlusion (Hi-Z)」チェックボックス。効果は Visible (GPU) / Draw calls (GPU) で見る
  rhi.h など        : SetOcclusionCullingEnabled / IsOcclusionCullingEnabled (既定 : 有効)
  Renderer / C#     : Renderer_SetOcclusionCulling、Renderer_TestGroundView、--occlusion on|off、--view ground

■ この先の案
  - 2 段階のオクルージョンカリング (前のフレームで見えていた物を先に描き、その深度で残りを判定し直す) : 1 フレーム遅れを無くす。
  - 深度バッファを直接 SRV で読む (写しを無くす。約 0.012 ms)。DENY_SHADER_RESOURCE を外し、ディスクリプタを用意する必要がある。
