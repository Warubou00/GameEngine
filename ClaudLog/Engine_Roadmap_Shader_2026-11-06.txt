エンジンのロードマップ : シェーダー / 雲 / プリミティブ / シェーダーノード 2026-11-06

■ 頼まれたこと
  GameEngine.Editor/assets の hlsl / pptx / ノイズのテクスチャを解析し、今のエンジンで見られるようにする。その時に :
    1. プリミティブ (立方体 / 球 / トーラス / 円柱 など) を足す。雲の描画には立方体を使う
    2. シェーダーノードの窓 (Unity / UE のマテリアルのように出力までノードを繋ぎ、シェーダーにコンパイルしてマテリアルに付ける。プレビュー付き)

■ 解析した結果
  volumetricCloud2.hlsl (Shift-JIS) : 立方体の中をレイマーチする雲海
    - 雲海の濃さ = clamp((雲海の最高点 - レイの位置.y) / 雲海の深さ, 0, 1)
    - 3D の Perlin / Worley ノイズを混ぜ、透明度 = clamp((ノイズ × 濃さ - 補正値) × 乗算値, 0, 1)
    - 色 = lerp(雲の色, 影の色, 1 - 透明度) (法線を使わないライティング)
    - ゲルストナー波で頂点を動かす VS (雲海の面) もある
    - 別のエンジンのヘッダー (ShaderHeader / CBuffer / Function.hlsli) と、3D テクスチャ (t6 / t7) を前提にしている
    - 気になる点 : 透明度がループの最後の 1 歩の値だけになる (スライドではレイの中で一番大きい値) /
                   ワールドの歩幅が立方体の大きさに合っていない
  CEDiL_1919_0.pptx (110 枚) : CEDEC 2019「ゼノブレイド2 のレイマーチングを使った雲表現」
    雲海 (Perlin-Worley 3D テクスチャ 128^3 + 濃さ + 補正値 / 乗算値) / 透明度で 2 色を混ぜるライティング /
    Value Noise (2D の乱数テクスチャの R・G をずらして 3D に見せる) / 空雲 (SkyMap) / モデル雲 (凸メッシュの中) /
    縮小バッファ / 初めの位置を求めてからレイを進める、など (資料の中身は写さず、手法だけを使う)
  ノイズのテクスチャ : 全部グレースケールの 2D (perlin / worley / value の 128x128、fbm 512x512、大きい value / perlin / worley)
    worley / value の 128 は端が繋がらない (タイルにならない)。シェーダーが読む 3D テクスチャは入っていない → エンジンで作る

■ 今のエンジンで足りない物
  - メッシュは .obj / .pmx のファイルからだけ (コードで作れない) → プリミティブが作れない
  - シーンは 1 つの共通シェーダー (hlslTemplate) を GPU カリング + ExecuteIndirect でまとめて描く。マテリアルは 色 / テクスチャ / 金属 / 粗さ だけ
    → マテリアルごとの自分のシェーダー (雲 / ノードで作った物) を描く道が無い
  - 3D テクスチャが無い (bindless は Texture2D の配列だけ)
  - 実行中に文字列の HLSL をコンパイルして PSO を作る口が無い (今はファイルのシェーダーだけ)

■ 段階 (1 つずつ「確認済み、マージして」で進める)
  SH1 : プリミティブ
    C++ : コードで作ったメッシュを登録する口 (Renderer_CreateMesh : 頂点 / インデックスの配列)
    C# : 立方体 / 球 / トーラス / 円柱 / 円錐 / カプセル / 平面 / クアッドを作る (分割数を選べる)。GameObject > 3D Object メニュー、
         コライダーも形に合わせて付ける。シーンには「組み込みの形 + 分割数」で保存する (ファイルを作らない)。書き出したゲームでも同じ
  SH2 : 自分のシェーダーを持つマテリアル
    C++ : 文字列の HLSL を実行中にコンパイルして PSO を作る (シーンと同じルートシグネチャ。VS は共通、PS を差し替え) /
          自分のシェーダーの物は、まとめて描く道とは別に描く (不透明 / 半透明、両面、深度を書くか) /
          3D テクスチャ (データから作る。bindless の Texture3D の範囲を足す)
    C# : Material に Shader (アセット) とパラメーター (シェーダーの中の印から読む : float / 色 / ベクトル / テクスチャ) を足す。
         インスペクターで値を変えるとすぐ反映。シェーダーのファイルを保存すると読み直す。コンパイルのエラーは Console に行と一緒に
  SH3 : 雲 (立方体の中のレイマーチ)
    ユーザーの volumetricCloud2.hlsl を SH2 の形に移す (Shift-JIS → UTF-8。上の気になる点を直す : 透明度はレイの中で一番大きい値 /
    立方体の中だけを進む / 入った所から始める)。3D の Perlin-Worley / Value ノイズ (128^3) をエンジンで作ってキャッシュ。
    渡された 2D のノイズも使える。見本のシーン clouds (立方体の雲をいくつか + 雲海の面 (ゲルストナー波) は余裕があれば)。
    書き出したゲームでも同じに見える (シェーダーとノイズも書き出しに入れる)
  SH4 : シェーダーノードの窓
    ImGui でノードの画面 (置く / 繋ぐ / 消す / 元に戻す / 拡大・移動)。入力 (UV / 位置 / 時間 / カメラの向き / 頂点の色) /
    定数 / パラメーター / テクスチャ (2D / 3D) / 計算 (四則 / lerp / clamp / dot / pow / sin ...) / ノイズ / 分解・合成 /
    出力 (色 / 透明度 / 放射 / 金属 / 粗さ)。保存は .shadergraph.json (アセット)。HLSL を作って SH2 の道でコンパイルし、マテリアルに付ける。
    エラーのあるノードを赤く
  SH5 : プレビューと雲のノード
    ノードの窓のプレビュー (球 / 立方体 / 平面に今のグラフを描く。回せる) / ノードごとの小さいプレビュー (余裕があれば) /
    「立方体の中をレイマーチ」のノード (雲をノードで組めるように)
