1. 高速化 : CPU と GPU の並列化 (FrameContext)  [2-3]
--------------------------------------------------------------------------------
  以前 : 1 フレームごとに「記録 → 送信 → GPU の完了を待つ」。GPU が描いている間 CPU は止まっていた。
  今回 : FrameContext (アロケーター + フェンス値) を FRAME_COUNT(=2) 個持ち、交互に使う。

           CPU : [記録 0][記録 1][記録 0'] ...
           GPU :         [実行 0][実行 1] ...
                          ↑ GPU がフレーム 0 を実行中に、CPU はフレーム 1 を記録できる

    - RenderStart : そのフレームの FrameContext を GPU が使い終わるまで待つ (2 フレーム前なので通常は待たない)
                    → アロケーターとコマンドリストをリセット
    - RenderEnd   : 送信 → Present → フェンス値をシグナルして記録するだけ (待たない)
    - コマンドリストは 1 本を使い回す (ExecuteCommandLists の直後に別のアロケーターでリセットできるため)

  [CPU が書き換えるデータもフレームごとに分けた]
    View / Projection の定数バッファを、フレーム数 × 256byte の領域にした。
    GPU が前のフレームで読んでいる最中の値を、CPU が次のフレーム用に上書きしてしまうのを防ぐため。
    - UpdateViewProjection は CPU 側の行列を更新するだけ
    - 毎フレーム Buffer::WriteFrameConstants(frameIndex) でそのフレームの領域へ書く
    - 行列が変わっていないフレームは書き込みを省く (UPLOAD ヒープは CPU から遅いメモリなので無駄に書かない)

  [アップロード用のコマンドリストを分けた]
    描画用 (フレーム) と アップロード用 (即時) を別のアロケーター / コマンドリストにした。
    ロード中のアップロードが描画用の状態を壊さない。
    GetGraphicsCommandList() はアップロード用を返す (Buffer / Texture のアップロードはそのまま動く)。
    ※即時用は送信のたびに完了を待つので、ロード時専用 (毎フレーム呼ぶと遅くなる)

2. 高速化 : 表示まわり
--------------------------------------------------------------------------------
  - バックバッファを 2 → 3 枚 (表示中・描画中の他にもう 1 枚あるので、CPU が待たされにくい)
  - Frame Latency Waitable Object
      SetMaximumFrameLatency(FRAME_COUNT) + RenderStart の最初で待機。
      CPU が表示より先行しすぎて入力遅延が増えるのを防ぐ (並列化しても遅延は増やさない)
  - テアリング (DXGI_FEATURE_PRESENT_ALLOW_TEARING)
      対応環境では VSync OFF 時に DXGI_PRESENT_ALLOW_TEARING を付ける。
      付けないと VSync OFF でもリフレッシュレートで頭打ちになる環境がある。可変リフレッシュレートにも必要。
  - 深度バッファの高速化
      最適化クリア値 (1.0) を指定して作成し、同じ値でクリアする (高速クリアが効く)
      DENY_SHADER_RESOURCE を付けて、ドライバーが深度圧縮を最適化できるようにした
  - Render のループで、頂点オフセットのルート定数が前回と同じなら設定を省く
  - C# : 最小化中は描画せず 16ms 休む (見えないのに CPU / GPU を回さない)
  - Alt+Enter での DXGI 任せのフルスクリーン切り替えを無効化 (バッファの作り直しが必要になり落ちるため)

3. ウィンドウのリサイズ  [2-4]
--------------------------------------------------------------------------------
  - RHI_Resize(width, height) を DLL に追加。C# の ClientSizeChanged から呼ぶ
  - CommandContext::Resize : GPU の完了待ち → バックバッファ参照を手放す → ResizeBuffers
                             → RTV と深度バッファを作り直す
  - Buffer::SetViewportSize : Projection のアスペクト比を描画先のサイズに合わせる
                              (以前は 1280x720 固定)
  - 最小化中 (サイズ 0) は何もしない
  - RTV はこれまで Buffer (DescriptorHeapManager) で作っていたが、CommandContext の持ち物にした
    (描画先と一緒に作り直す必要があるため)
    ※DescriptorHeapManager の RTV ヒープ (2 個分) は使われなくなった。Phase 2 で整理する

4. 深度バッファ  [2-6]
--------------------------------------------------------------------------------
  - D32_FLOAT、クリア値 1.0、比較 LESS (手前のものが残る)
  - PSO の DSVFormat と CommandContext::DEPTH_FORMAT を同じ定数にした (ずれるとエラーになる)
  - ResourceBuffer::CreateDepthStencil を追加

6. C# (GameEngine_console)
--------------------------------------------------------------------------------
  - ウィンドウのサイズを外枠 (Width/Height) ではなく描画領域 (ClientSize) で指定・送信  [2-4]
  - RHI_Initialize の RHIInfo を ref で渡す (C++ はポインタで受ける)  [2-12]
    以前は値渡しで、x64 の呼び出し規約がたまたま参照で渡していたため動いていた
  - RHI_Resize の戻り値 bool は MarshalAs(I1) (C++ の bool は 1 バイト)
  - メインループを while(true) → while(rhi.IsOpen) にし、終了時に rhi.Dispose() を呼ぶ
    (以前はウィンドウを閉じても RHI_CleanUp が呼ばれなかった)
  - タイトルバーに FPS / フレーム時間 / 描画サイズを表示 (0.5 秒ごと)

7. 気づいた問題 (今回は未対応)
--------------------------------------------------------------------------------
  - Core/Source/Math/Vector/math/MyMath.cpp : C4172「ローカル変数のアドレスを返します」が 20 件以上。
    関数を抜けると無効になる参照を返しているので、使っている箇所があれば未定義動作。要修正。
  - バックフェイスカリングは無効のまま (CULL_MODE_NONE)。
    閉じたメッシュなら有効にするとピクセルシェーダーの実行が約半分になるが、
    OBJ (右手系) と DirectXMath (左手系) で面の向きが逆になるので、ローダー側で揃えてから有効にしたい。
  - アップロードは即時コマンドで毎回 GPU の完了を待つ (ロードが遅い)
    → Phase 2 : COPY キュー + アップロード用リングバッファ (3-4)
  - Scene 定数バッファ (オブジェクトごと) はロード時に書くだけなので今は安全だが、
    毎フレーム書き換えるようになったら、View/Projection と同じくフレームごとに分ける必要がある
