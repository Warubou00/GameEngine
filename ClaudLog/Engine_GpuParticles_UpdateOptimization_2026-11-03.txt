2. 切り分け (100 万個、ソート・衝突なし。シェーダーだけを出力先へ写して比べた)
--------------------------------------------------------------------------
 - 計算を全部外しても (読んで年齢だけ進めて書く) 1.75 ms → 計算ではなく、メモリの読み書きが遅い
 - 起動直後の 2 秒 (空きリストを先頭から使うので、パーティクルの番号がメモリの順に並んでいる) は約 94 万個で 0.86 ms、
   死んだ物の番号を使い回し始めると同じ数で 1.2〜1.7 ms → 番号がばらばらになり、64byte をランダムな場所から読み書きしていた
 - 詰め直す形にした後も 1.05 ms で、計算を外しても 1.17 ms。順に読み書きしているのに実効の帯域が約 128 GB/s しか出ていなかった
   → 1 スレッドが 64byte の構造体を、隣のスレッドと 64byte 離れた所から読み書きしていたため (16byte ずつの読み書きにしても 1.07 ms)

--------------------------------------------------------------------------
3. やったこと
--------------------------------------------------------------------------
 ① 詰め直し (資料の Particle Binary の詰め直しに近い)
    - パーティクル本体を 2 本にして毎フレーム入れ替える。更新は入力を先頭から順に読み、生き残りを出力の先頭から詰めて書く
    - 空きリスト / (キー, 番号) の列 2 本 / 番号の経由 が無くなった。発生は入力の末尾に書く
    - 100 万個 : 更新 1.77 → 1.16 ms、ソートなしの描画 1.13 → 0.80 ms (出した順に並ぶので、続けて描く四角が近い場所に集まる)
 ② 本体を 16byte × 4 枚 (SoA) に分ける (位置・年齢 / 速度・寿命 / エミッター・大きさ・色 / 回転・角速度・乱数・フラグ)
    - 1 命令で Wave の全スレッドが連続した 512byte を読み書きする。100 万個 : 更新 1.05 → 0.55 ms
    - ただし、ソートした描画は 1 個につき 4 か所を読むので 1.18 → 2.35 ms に増えた
 ③ 描画用 32byte を更新で書き出す (資料の Build Primitive に当たる)
    - 位置・大きさ / 色 (half4) / 回転 (伸ばす物は「速度 × 伸ばす秒」の向きと長さを half3) / 形とフラグ
    - 頂点シェーダーはこれだけを読む (本体は読まない)。ソートした描画 2.35 → 1.16 ms、更新は書き出しの分 0.55 → 0.72 ms
    - 比べた形 (100 万個・ソートあり、フレームの GPU) : 構造体のまま 2.88〜2.95 ms / SoA だけ 3.50 ms / SoA + 描画用 2.57〜2.62 ms
