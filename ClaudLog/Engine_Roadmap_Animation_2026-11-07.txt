ロードマップ : FBX とアニメーション (AN1 → AN5) 2026-11-07

■ 頼まれた事
  FBX を読む (外部ライブラリを使わず、自分で書いたコードで読む)。3 種類のアセット :
    xxxx.mod.fbx = モデル (マテリアルを含む) / xxxx.skl.fbx = スケルトン / xxxx.anm.fbx = アニメーション
    中身が名前と合わない時 (例 : .skl.fbx にスケルトンが無い) は読み取りエラー
  アニメーションは GPU のスキニングで速く。モデルと階層型アニメーションのプレビューの窓
  サンプルは無いので、自分で FBX を作ってよい

■ 今のエンジン (調べた事)
  - モデルは C++ (Renderer/Source/Loader の OBJ / PMX) で読む。プリミティブ (SH1) は C# で頂点を作り Renderer_CreateMesh で渡す
  - 頂点は 1 つの大きな頂点バッファ (56 byte の Vertex) にまとめ、シェーダーが StructuredBuffer として読む。描画ごとに BaseVertex
  - 描画は GPU で選別 (カリング) して ExecuteIndirect でまとめて描く。影 (3 段) / 深度 / SSAO / 自分のシェーダーも同じ頂点を読む
  - スキニング / 骨 / アニメーションは無い (PMX の骨は読み飛ばしている)
  - エディターのシーンビューは描いたテクスチャを ImGui.Image で出す。視点 (カメラ) は 1 つ (他は影のカスケード)

■ 方針 (大きな決め事)
  1. FBX は C# (Runtime) で読む。バイナリの FBX 7.1 〜 7.7 (7.5 から長さが 64bit)
     - 圧縮された配列 (zlib / deflate) を読む inflate も自分で書く (.NET の ZLibStream は使わない。テストの比べ相手にだけ使う)
     - C# にする理由 : テストしやすい / エディターの取り込み・エラー表示と同じ所 / 書き出したゲームも同じコード
     - ASCII の FBX と FBX 6 以前は最初は読まない (エラーで「バイナリで書き出して」と出す。後で足せる)
  2. 3 つの拡張子は別のアセットの種類 (AssetKind.FbxModel / FbxSkeleton / FbxAnimation)。中身を確かめてエラーにする :
       .mod.fbx : メッシュ (Geometry) が 1 つも無い → エラー
       .skl.fbx : 骨 (LimbNode / Null の階層) が無い → エラー
       .anm.fbx : アニメーション (AnimationStack と曲線) が無い / 動く値が 1 つも無い → エラー
     エラーは Console と Inspector と Project のタイル (赤) に出す。読めた物は Inspector に数 (頂点 / 骨 / 長さ) を出す
     モデル / アニメーションと スケルトンの繋がりは骨の名前で合わせる (合わない骨は警告)
  3. 座標と単位 : FBX の GlobalSettings (UpAxis / FrontAxis / CoordAxis / UnitScaleFactor) を読み、エンジン (左手系 / Y 上 / m) に変える
     変換の式 : 親 × T × Roff × Rp × Rpre × R × Rpost⁻¹ × Rp⁻¹ × Soff × Sp × S × Sp⁻¹ (回転の順番 RotationOrder も)
  4. アニメーションは読み込む時に決まった刻み (FBX の TimeMode。無ければ 30 fps) で骨ごとの 位置 / 回転 (四元数) / 大きさ にしておく
     (曲線の補間 : 一定 / 直線 / 3 次 を読み込みの時に計算。毎フレームは刻みの間を直線 / 球面線形で補うだけ)
  5. GPU のスキニングは「計算シェーダーで 1 回だけ変形して、大きな頂点バッファの、その物専用の場所に書く」
     → 後の描画 (GPU のカリング / 影 3 段 / 深度 / SSAO / 自分のシェーダー / ピッキング) は今のまま変形後の頂点を読む
     (頂点シェーダーで変形すると、影 3 段 + 深度 + 本描画で 1 フレームに 5 回変形することになる)
     骨の行列は毎フレーム 1 回の P/Invoke でまとめて送る。1 つの頂点に骨 4 本まで (多い時は重い 4 本にして足して 1 に)
     カリングの箱は骨の位置から毎フレーム作る (読み込む時に骨ごとの頂点の広がりを調べておく)
  6. 読み込んだ結果はプロジェクトの Library/Fbx にキャッシュする (2 回目から速い。書き出したゲームにも入れる。Noise3D と同じ)

■ 段階 (それぞれブランチ → 確認 → マージ。各段で EditorTest / 時間 / ClaudLog)

  AN1 : FBX を読む土台 + 自作のサンプル
    - inflate (zlib) を自分で書く : 格納 / 固定ハフマン / 動的ハフマン、Adler-32 の確認
    - FBX のノードの木を読む (ヘッダー / 版 / 32・64bit の記録 / プロパティ Y C I F D L S R と配列 f d l i b / 圧縮)
      Objects (Geometry / Model / Material / Texture / Deformer / Pose / AnimationStack / Layer / CurveNode / Curve) と Connections を引ける形に
    - 自作の FBX を書く物 (テスト用の FbxWriter) : 箱 / 腕のように曲がる円柱 (骨 3 本と重み) / 歩くような動き / 階層のロボット
      配列は圧縮あり・なしの両方を書く (圧縮は .NET の ZLibStream で作り、自分の inflate で戻せるかを確かめる)
    - 拡張子で種類を分け、中身が足りない時はエラー (.skl.fbx に骨が無い など)。Project のアイコン / Inspector に中身の数と エラー
    - テスト : inflate を乱数のデータで ZLibStream と比べる / 壊れたファイル (途中で切れた / 版が違う) がエラーになり落ちない

  AN2 : モデル (.mod.fbx)
    - メッシュ : 多角形 → 三角形 (凹みもある物は耳を切る方法)、法線 / UV / 頂点色 (点ごと / 多角形の頂点ごと、Direct / IndexToDirect)
    - マテリアル : Lambert / Phong の色 / テクスチャ (ファイルの名前を Assets から探す) → 今のマテリアル。マテリアルごとに分けて描く
    - 座標 / 単位の変換、ノードの変換 (Geometric も)。メッシュが複数でも 1 つのモデル
    - シーンに置ける (Project からドラッグ / MeshRenderer の Model の欄)。書き出したゲームでも同じ
    - スキンの重み (Deformer の Skin / Cluster) と バインドポーズも読んでおく (描くのは AN4)
    - テスト : 自作のモデルの頂点数 / 面 / マテリアル / 箱の大きさ、OBJ で同じ形の物と見た目を比べる、時間 (読み込み ms)

  AN3 : スケルトン (.skl.fbx) と アニメーション (.anm.fbx)、CPU で動かす
    - スケルトン : 骨の階層 / バインドポーズ / 名前。アニメーション : 骨ごとの曲線 → 決まった刻みの姿勢 (長さ / fps / ループ)
    - コンポーネント Animator (Skeleton / Clip / Speed / Loop / 再生中か / 時間)、AnimationSystem が毎フレーム姿勢を作る
    - 階層型アニメーション : スキンの無いメッシュが骨の子になっている物 (ロボットのような固い部品) も骨に付いて動く
    - 骨を線で描く (エディター / デバッグ表示)。再生ボタン / 書き出したゲームと同じ動き (決まった刻みで比べる)
    - テスト : 自作の曲線の値 (直線 / 一定 / 3 次) の刻みの値、骨の世界の位置、ループ、骨の名前が合わない時の警告

  AN4 : GPU のスキニング
    - C++ / RHI : 変形前の頂点 + 骨の番号 4 つ / 重み 4 つ のバッファ、骨の行列のバッファ (毎フレーム)、計算シェーダー (skinning.shader)
      で変形して大きな頂点バッファの専用の場所へ書く (法線も)。物ごとに BaseVertex が違う → 今の描画の道でそのまま描く
    - カリングの箱を毎フレーム、影も変形した形、自分のシェーダーのマテリアルでも動く
    - 時間を測る : 例えば 1 体 1 万頂点 × 100 体 / 骨 50 本 で、GPU のスキニングの時間 / C# の姿勢の計算の時間 / フレームの時間
      (目安 : スキニングは 0.2 ms 以下、C# は 0.2 ms 以下を目指す。測って正直に書く)
    - テスト : GPU で変形した頂点を読み戻して、C# で同じ計算をした物と比べる (誤差)、Debug の D3D12 の検証でエラー 0

  AN5 : プレビューの窓
    - FBX のアセットをダブルクリック (またはメニュー) で開く窓。シーンとは別の小さな世界をその窓の中で描く
      (RHI : 2 つ目の視点と描画先、物ごとの「どの視点に出すか」の印。シーンの物はプレビューに出ず、プレビューの物はシーンに出ない)
    - モデル : 回して見る (右ドラッグ / ホイール)、床と格子、ワイヤーフレーム / 法線 / 骨の表示の切り替え、マテリアルの一覧
    - スケルトン : 骨の木 (選ぶとその骨が光る)、名前
    - アニメーション : モデル + スケルトン + クリップを選んで再生 / 止める / 時間のバーで動かす / 速さ / ループ、今の時間とフレーム
    - テスト : 窓を開いて再生し、時間のバーを動かすと骨の位置が変わる / 窓を閉じると描く物が残らない / 撮った絵

■ やらない事 (最初は)
  ASCII の FBX / FBX 6 以前 / モーフ (ブレンドシェイプ) / アニメーションの混ぜ合わせ (クロスフェード) / IK / ルートモーション /
  カメラ・ライトのアニメーション / 1 頂点 5 本以上の骨 (4 本にまとめる)。必要になったら AN6 以降

■ 確かめ方
  各段 : EditorTest (Release / Debug、D3D12 の検証 0) / エディターと書き出したゲームの絵を撮る / 時間を測る / ClaudLog
  本物の DCC ツールで書き出した FBX (Blender / Maya / Mixamo など) でも確かめたい :
    手元にあれば Assets に置いてもらう、またはネットの無料のサンプルを落とす (落とす時は先に許可を貰う)
