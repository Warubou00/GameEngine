■ 今のエンジンで前提になること (調べた結果)
  描画
    - GPU カリング (視錐台 + 2 段階の Hi-Z オクルージョン) は「1 フレーム 1 回、最初の不透明の DrawScene」で行う。
      カメラ以外の視点 (ライト) から描くパスは無い。→ 影には「視点ごとのカリング」と「視点ごとの定数 (View / Proj)」が要る
    - 描画先は C# の RenderTexture (色のみ) + SceneDepth (1 つ)。深度だけのテクスチャを C# から作る手段が無い
    - サンプラーは s0〜s2 (比較サンプラー = 影の PCF 用が無い)
    - ライトは StructuredBuffer (平行光源 / 点光源)。影の情報は無い
  ECS (C#)
    - Transform は位置 / 回転 / 大きさ + 行列。親子関係は無い
    - 毎フレームの可変 DeltaTime だけで、固定の時間刻み (FixedUpdate) が無い → 物理には固定刻みが要る
    - メッシュの境界 (AABB / 球) は C++ (RHI) 側にだけある。C# からは見えない
  DLL の形 : C ABI + ハンドル (番号 + 世代) + 毎フレームの値は配列でまとめて 1 回 (Renderer / Audio / Controller と同じ)

■ 全体の順番 (各段で見た目の確認 → 「確認済み、マージして」で次へ。E3 と同じ進め方)
  1. シャドーマップ     S1 → S2 → S3

  影と衝突判定は互いに依存しないので、順番は入れ替えられる (おすすめは影から : 描画の土台の変更が先に済む)

====================================================================
 1. シャドーマップ
====================================================================
  S1 : 土台 + 1 枚のシャドーマップ (平行光源 1 つ)
    RHI
      - 深度だけのレンダーターゲット (D32 / D16。SRV で読める。配列も可) を RenderTexture から作れるようにする
      - 「視点」を複数持てるようにする : FrameData をパスごとの定数に分ける (カメラ / ライト × カスケード数)
      - 視点ごとのカリング : シャドーパスはライトの視錐台で GPU カリング (オクルージョンはしない)
          今の「1 フレーム 1 回」の作りを、DrawScene に視点の番号を持たせる形に広げる
      - 深度だけの PSO (ピクセルシェーダー無し。半透明は描かない / アルファテストのみ。デプスバイアス + 傾斜バイアス)
      - 比較サンプラー (s3) を追加
    シェーダー
      - 平行光源 1 つ目に影 : PCF (3x3 の比較サンプル)、法線方向のオフセットでシャドーアクネを抑える
      - Forward / Deferred の両方 (Deferred はライティングの全画面パスで読む)
    C#
      - DirectionalLight.CastShadows / Graphics.Shadows (解像度・距離・バイアス・PCF)
      - パイプラインにシャドーパスを追加 (RenderPipeline の部品 : ShadowPass。SsaoPass と同じ形)
    確認 : 箱・岩・キャラクターの影が地面に落ちる / 影の付け根の浮き (ピーターパン) とアクネが目立たない
    計測 : 影なしとの差 (GPU)

  S2 : カスケード (CSM) と効率化の検討 ← ご依頼の「カスケードによる効率化の検討」
    実装
      - 2〜4 段 (既定 3〜4)。Texture2DArray に段ごと。分割は対数と均等の混ぜ合わせ (λ を設定可能)
      - 揺れ (シマリング) 対策 : 段を境界球で囲み、ライト空間でテクセル単位に位置を丸める
      - ピクセルシェーダーでビュー空間の深さから段を選ぶ。段の境目は少し重ねてなだらかにつなぐ
      - 影を落とす物がカメラの外にあっても入れる (ライトの方向へ近い側を伸ばす)
    比べて決める (それぞれ計測して ClaudLog に表で残す)
      a. 段の数 2 / 3 / 4 と解像度 (1024 / 2048) : 画質と GPU 時間
      b. 段ごとのカリング : 段ごとに GPU カリング vs 全段を囲む 1 回
      c. 段の描き方 : 段ごとに ExecuteIndirect vs 1 回で全段 (インスタンスで段を振り分け、SV_RenderTargetArrayIndex)
      d. 更新の間引き : 近い段は毎フレーム、遠い段は 2〜4 フレームに 1 回 (段ごとに順番に更新)
      e. 動かない物のキャッシュ : Static の物だけ別に描いておき、動く物だけ重ねる (遠い段で効く)
      f. 影の読み方 : Forward で直接読む vs 画面の影の濃さを 1 枚に先に作る (スクリーンスペースのシャドーマスク)
    おすすめの最初の形 : 4 段 / 2048 / 段ごとのカリング / 間引きあり。計測で変える
    確認 : 近くはくっきり、遠くまで影がある / カメラを動かしても影がちらつかない (F キーで段を色分けして表示)

  S3 : 仕上げ (必要なら)
    - 点光源の影 (キューブマップ。6 面なので重い。数を限る) / 影の柔らかさ (PCSS) は要望があれば

 2. 衝突判定 (高速化重視)
====================================================================
  置き場所 : C++ の新しい DLL (Physics.dll。Audio.dll と同じ C ABI) をおすすめ
    - 理由 : SIMD (DirectXMath) が使いやすい / 将来の並列化 / Renderer と同じ層の形
    - C# とのやり取り : 動いた物の行列を配列で 1 回送り、結果 (接触の一覧 / 物理で動いた行列) を配列で 1 回受け取る
      (RenderSyncSystem と同じく、動いた物だけ送る)
    - 代わりの案 : C# だけで作る (受け渡しが無い、デバッグしやすい。速さは C++ の 7〜8 割の見込み)
      ※ここは着手前に一度決めたい (下の「決めておきたいこと」)

  C1 : 土台 + ブロードフェーズ (候補の組を速く絞る)
    - コライダー : 球 / 箱 (OBB) / カプセル。C# のコンポーネント Collider + 衝突のレイヤー (どれ同士を調べるか)
    - ブロードフェーズ : 動的 AABB ツリー (BVH) を「動かない物」と「動く物」で 2 本に分ける
        動かない物 (Static) の木は作った後ほぼ変えない。動く物は少し太らせた AABB を使い、はみ出した時だけ木を直す
        → 動いた物だけを両方の木に問い合わせる (全部 × 全部 を調べない)
    - 結果 : 重なり始め / 重なっている / 離れた のイベント (C# の OnCollisionEnter のような形) を配列で返す
    - デバッグ表示 : コライダーを線で描く (RHI に線の描画を足す。確認と調整に必要)
    計測 : 総当たり / 均一グリッド / BVH を 1,000〜20,000 個で比べる (目標 : 1 万個の動く物で 1 ms 未満)

  C2 : ナローフェーズ + クエリ
    - 形ごとの判定 : 球-球 / 球-箱 / 箱-箱 (分離軸) / カプセル系。接触点・法線・めり込み量 (物理で使う)
    - レイキャスト / 重なりの問い合わせ (Physics.Raycast / OverlapSphere)。木をたどるので速い
    - メッシュコライダー (動かない物だけ) : 三角形の BVH (地面や岩の形どおりに当たる)
      ※メッシュの頂点は今 C++ の Renderer にあるので、読み込み時に Physics 側にも渡す
  C3 : 速さの詰め
    - SoA (形ごとに配列を分ける)・SIMD の AABB 判定・ナローフェーズの並列化 (スレッド)
    - 計測して効いた物だけ残す (今までと同じ)

 3. 簡易物理 (衝突判定と一緒に作る)
====================================================================
  P1 : 固定の時間刻み + 剛体の基本
    - Engine に FixedUpdate (既定 60 Hz。足りない分は 1 フレームで最大 N 回進める) を足す
      描画は前後の 2 状態の間を補間して、カクつかないようにする
    - Rigidbody : 質量 / 速度 / 重力 / 反発 / 摩擦 / 動かない (Kinematic)
    - 接触の解決 : 逐次インパルス法 (数回の反復) + めり込みの押し戻し
      最初は回転なし (球・箱が滑る / 跳ねる / 積み重なる) で確認
  P2 : 回転と安定化 (必要なら)
    - 慣性テンソルで回転 (箱が転がる)、接触点のキャッシュ (反復の引き継ぎ)、眠り (止まった物は計算しない)
    - 確認用の見本 : 箱を積む / 球を坂に転がす / 1,000 個を落とす (計測)
