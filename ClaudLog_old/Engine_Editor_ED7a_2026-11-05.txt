■ [GameSystem] (エンジン。Ecs/ISystem.cs)
  付けた System は、エディターが自動で作って登録する (コンストラクターは (Engine) か ())。Order の順
  どのシーンでも動くので、自分の物の無いシーンでは何もしないように書く :
    LaserDemoSystem は OrbitMover のあるシーンだけ / PhysicsDemoSystem は StackBlock か MovingPlatform のあるシーンだけ
  → エディターの再生で、物理の見本の Space (球を撃つ) / R (作り直す) / 動く床 / レーザーも動くようになった
    (以前はエディターの Program で Spin などを 1 つずつ登録していた)
  Engine.AddGameSystems(assembly) / Engine.RemoveSystems(systems)

■ エディターのビルドと読み直し (ScriptHost.cs)
  - 起動時 : ソース (とフォルダ) より新しい Game.dll が無ければ dotnet build して待つ → 読み込む → シーンを開く
    (フォルダの日時も見る : .cs を消しただけの時も作り直す。最初は .cs の日時だけで、消した型が残った)
  - Project/Scripts の .cs を保存 → 0.5 秒後に dotnet build (別のスレッド。メニューの横に Compiling scripts...)
    → 成功 : 読み直す / 失敗 : エラーを Console に出し、前の Game.dll のまま (メニューの横に Script errors。マウスを乗せると 1 つ目のエラー)
  - 読み直し (EditorApp.ReloadScripts) : 再生中なら止める → シーンを JSON に → World を空に → [GameSystem] を外す →
    古い型の入れ物 (World.RemovePools) と型の情報 (ComponentRegistry.Forget) を捨てる → AssemblyLoadContext を捨てる →
    新しい Game.dll を読み、[GameSystem] を作る → JSON からシーンを作り直す (値は型の名前とフィールドの名前で引き継ぐ。足したフィールドは既定の値)
    選んでいる物はそのまま。元に戻すの記録は消す (古い型を持っているので)。保存していない変更の印 (*) はそのまま
  - Game.dll はファイルではなくバイト列で読む (ファイルを掴まないので、ビルドし直せる)。捨てられる AssemblyLoadContext
  - Scripts メニュー : Rebuild / Open Scripts Folder / 読み込んだ回数・System の数・ビルドの時間

■ 古い Game.dll を本当に解放する (メモリが読み直すたびに増えないように) : 3 つ直した
  1. World.GetPool(Type) : 以前は GetPool<T> を MakeGenericMethod で呼んでいた → World の型のリフレクションの覚えにゲームの型が残った。
     入れ物の型を MakeGenericType で作って直接作るようにした
  2. エディターの .NET の設定 TieredCompilationQuickJitForLoops = false (エディターだけ)。
     既定ではループのあるメソッドを軽い JIT で始めて後で JIT し直すが、そうするとエンジンのジェネリックなメソッドを
     ゲームの型で使った物 (World.ForEach<Transform, Spin> など) を再生で動かした後、古い DLL がいつまでも解放されなかった。
     調べた結果 : TieredCompilation=0 / TC_QuickJitForLoops=0 なら解放、TieredPGO=0 / TC_CallCounting=0 / TC_OnStackReplacement=0 では解放されない
     速さ : エディターの C# update 0.139 〜 0.140 ms (この設定) / 0.149 ms (既定)。遅くならない
  3. Engine.Run の中の foreach (System を回す) を別のメソッドに。Debug のビルドでは foreach の変数 (最後のゲームの System) が
     Run が終わるまで残り、解放されなかった (Release では 1 と 2 だけで解放された)
  調べ方 : 一時的な調べ (Debug の段階を足しながら、読み込み → 捨てる → GC → WeakReference を見る) で原因を絞った。調べのコードは消した
