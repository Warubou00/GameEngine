1. UploadManager (新規 : DirectX12/dx12_uploadManager.h/.cpp)  [3-4]
--------------------------------------------------------------------------------
  以前 : アップロードのたびに
           UPLOAD バッファを新規作成 → Map → コピー → Unmap → コピー命令 → 送信 → CPU で GPU の完了を待つ
         box.obj の読み込みだけで、これが 5 回 (既定テクスチャ / テクスチャ 2 枚 / 頂点 / インデックス) 起きていた

  今回 :
    1. Allocate       : 64MB の永続マップしたリングバッファから領域を切り出す (作成も Map も不要)
    2. GetCommandList : COPY 型のコマンドリストにコピー命令を積む (何回でも)
    3. Flush          : RenderEnd でまとめて 1 回だけ COPY キューへ送信 (CPU は待たない)
    4. 描画キューは ID3D12CommandQueue::Wait で、アップロード完了を GPU 上で待ってから描画する
    → CPU も描画キューも止まらない。COPY キューは描画と並行して転送できる

  リングバッファ
    - 使い終わった領域 (送信済みで GPU が完了したもの) はフェンス値で判定して自動で再利用する
    - 空きが無ければ未送信分を送信して、一番古い転送の完了だけを待つ
    - リングより大きいデータは一時バッファを個別に作り、転送完了後に自動で破棄する
    - コマンドアロケーターも送信ごとにフェンス値を持ち、完了したものから使い回す (最大 8 個)

  リソースの状態 (バリア)
    - COPY キューでは PIXEL_SHADER_RESOURCE などへのバリアを張れない。
      そこで「暗黙の状態昇格 / 減衰」を使い、アップロード側ではバリアを張らないようにした:
        COMMON → (COPY キューでコピー : 暗黙で COPY_DEST) → 完了後 COMMON に戻る
               → (描画キューで読む : 暗黙で PIXEL_SHADER_RESOURCE / 頂点 / インデックス)
    - そのためテクスチャの初期状態を COPY_DEST → COMMON に変更した (ResourceBuffer::CreateTexture)

  CommandContext の変更
    - 即時コマンドリスト (BeginRecording / ExecuteAndSync) を廃止し、UploadManager を持つようにした
    - SubmitUploads() : アップロードを送信し、描画キューに GPU 上で待たせる (RenderEnd が毎フレーム呼ぶ)
    - WaitForGpu() は描画キューと COPY キューの両方を待つ (終了・リサイズ時)
    - GetGraphicsCommandList() → GetUploadManager() に変更

2. テクスチャのデコードを並列化
--------------------------------------------------------------------------------
  - Texture::LoadTexturesFromFiles(paths) を追加
      1. 全ファイルのデコード (WIC) をワーカースレッドで同時に行う (スレッド数は CPU のコア数まで)
      2. GPU へのアップロード登録はメインスレッドで順番に行う (UploadManager はスレッドセーフではない)
  - Buffer::LoadModel は、テクスチャを使うマテリアルのパスを集めてまとめて読み込むようにした
  - 注意点 (コメントに記載)
      * ワーカースレッドごとに CoInitializeEx(MTA) する (WIC は COM)
      * WIC のファクトリーはメインスレッドで先に作っておく (ワーカーで初めて作ると、
        そのスレッドの終了と一緒に使えなくなる恐れがある)
      * デコード結果はアップロード領域にコピーした直後に解放 (ピークメモリを抑える)
  - dx12_textureManager を「デコード (DecodeImageFile)」と「アップロード (CreateTextureFromImage)」に分割
  - 行の長さが同じ画像は、行ごとの memcpy ではなく 1 回の memcpy でコピーする


--------------------------------------------------------------------------------
3. DescriptorHeapManager の整理
--------------------------------------------------------------------------------
  - 使われていなかった RTV ヒープ (Phase 1 で CommandContext に移した残り) と、
    作成もされていなかった DSV / Sampler ヒープのメンバーを削除
  - SRV ヒープを DescriptorHeap ラッパーで持つようにした
    (以前はハンドルを取るたびに GetCPU/GPUDescriptorHandleForHeapStart を呼んでいた)
  - SRV ヒープのサイズを 1,000,000 → 65,536 に縮小 (約 32MB → 約 2MB)
    シェーダーのテクスチャ配列は 4096 個なので十分。ヒープが小さいほど作成も速くメモリも少ない

5. 今回やらなかったこと (Phase 2 の残り)
--------------------------------------------------------------------------------
  - ハンドル化 (3-1) とリソースの状態追跡
      API の形そのものを変える作業なので、抽象化の見直し (Phase 3) と一緒に行う方が手戻りが少ない
  - 遅延解放キュー
      現状は実行中にリソースを破棄する箇所が無い (リサイズは GPU 完了待ちで対応済み)。
      テクスチャの差し替え・アンロードを作る時に、FrameContext のフェンス値を使って追加する
  - さらなるロード高速化の候補
      * テクスチャを事前に DDS (BC1/BC7 圧縮 + ミップマップ) に変換しておく
        → WIC のデコードが不要になり、VRAM も 1/4〜1/8 になる。今回のボトルネックに一番効く
      * ファイル読み込み自体の非同期化 (ロード中も描画を止めない)
