 マテリアルごとの描画 / 複数モデル (OBJ + PMX) / PMX ローダーの移植

■ 概要
  - RHI にマテリアル (テクスチャ / 色 / ブレンドの方法) を追加し、描き方 (PSO) ごとに分けて描くようにした
      不透明 → 半透明 (アルファブレンド) の順。GPU カリング・詰め直し・2 段階オクルージョンも描き方ごとに対応
  - DirectX11 時代の PMX ローダーを今の Renderer に合わせて作り直し、VS のプロジェクトに登録した
  - モデルのフォルダ構成の変更 (Model/obj, Model/pmx/<名前>) に合わせてパスを直した
  - 見本のシーン (箱 + 岩 4 個 + PMX のキャラクター) を追加し、描画を確認した

■ モデルのパス
  - サンプルのパスを ../Model/obj/box.obj に変更 (C# の Program.cs / Samples/Showcase.cs)
  - Release の出力フォルダの Model も Debug と同じ構成 (obj / pmx) に揃えた (bin は git の管理外)

■ PMX ローダー (Renderer/Source/Loader/pmxLoader.h / .cpp)
  - 今の IModelLoader (Mesh を返す) に合わせて作り直し、Renderer.vcxproj / .filters に登録
    (元のファイルは Shift-JIS だったので、他の編集したファイルと同じく UTF-8 (BOM 付き) にした)
  - 読むもの : 頂点 (位置 / 法線 / UV) / 面 / テクスチャ / 材質 (色 / 両面フラグ / テクスチャ / 面の数)
    読まないもの : ボーン / モーフ / 剛体 / ジョイント (アニメーションを入れる時に追加)
  - 以前のローダーの不具合を直した
      - 追加 UV を 2 回読んでいて、追加 UV のあるモデルでは以降の位置がずれていた
      - 1 / 2 byte の符号付きの番号を符号拡張しておらず、「無し (-1)」が 255 / 65535 になって配列の外を読んでいた
      - 文字列を 512 文字の固定の配列に読んでいて、長い文字列で配列の外に書いていた
      - UTF-8 のモデル・PMX 2.1 を読めなかった
  - MMD と同じく、PMX の材質は全部「半透明」として、ファイルの材質の順番に、深度も書きながら描く
  - モデルの拡張子 (.obj / .pmx) でローダーを選ぶ (SceneRenderer::LoadModel)

■ OBJ ローダーの修正 (objLoader.cpp)
  - 同じマテリアルを usemtl で 2 回以上使うと、2 回目以降のマテリアルが nullptr になってテクスチャが付かなかった
    (rock.obj の Material.104)。最初のものを写して使うようにした
  - 中身は Shift-JIS → UTF-8 (BOM 付き) にした

■ テクスチャのパス
  - rock.mtl は Rock030_1K_Color.png / Rock032_1K_Color.jpg を指しているが、実際のファイルは .jpg / .png (拡張子が逆)
    アセットは変えず、エンジン側で「ファイルが無ければ同じ名前で拡張子の違う画像を探す」ようにした (ログに出す)
  - 同じテクスチャを使う材質が多い (PMX) ので、同じパスは 1 回だけ読む

■ テクスチャの圧縮 (dx12_textureManager.cpp)
  - 半透明のある画像は BC7 で圧縮していたが、4096x4096 の PMX のテクスチャで初回の変換に 1 枚 約 60 秒 (Release) かかった
    (Debug では数分)。BC7 の圧縮は CPU ではとても重い
    → 半透明があって 1024x1024 より大きい画像は BC3 にした (同じ 1/4。少し粗いが、圧縮が桁違いに速い)
       初回の読み込み : 約 59 秒 → 1.1 秒 (Release) / 3.0 秒 (Debug)。2 回目以降 (キャッシュ) は 26 ms
  - キャッシュは一時ファイルに書いてから名前を変える (書いている途中で終了しても壊れたキャッシュが残らない)

■ マテリアルと描き方 (RHI)
  - rhiTypes.h : MaterialDesc (テクスチャ / 色 / BlendMode) / MaterialHandle、DrawItem に Material を追加
                 ObjectConstants からテクスチャの番号を外し、ワールド行列だけにした (80 → 64 byte)
  - rhi.h      : CreateMaterial
  - Buffer     : マテリアルの表 (最大 4096)。増えた時だけフレームごとの UPLOAD 領域に書いて VRAM へ写す
  - シェーダー : DrawData にマテリアルの番号 (8 → 16 byte)。頂点シェーダーがマテリアルを引き、色とテクスチャの番号をピクセルへ
                 色 = 頂点の色 × テクスチャ × マテリアルの色
                 半透明用のピクセルシェーダー (PSAlphaBlend) は完全に透明な所を捨てる (不透明用は early-Z が効くよう捨てない)
  - Pipeline   : PSO を 2 つ (不透明 / アルファブレンド)。ルートパラメータにマテリアル (t3) を追加
  - CommandContext
      - 描画のまとまりの鍵に「描き方」を足し、引数を描き方ごとに並べる (不透明 → 半透明)
        半透明の先頭は 64 の倍数 (カリングの詰め直しは 64 個ずつまとめて処理するため。間は空の描画で埋める)
      - 描き方ごとに PSO を設定して描く (ExecuteIndirect / 1 個ずつ / GPU カリングの全ての経路)
      - GPU カリング : 詰め直しを描き方ごとに分ける (カウンターと書く場所が別)
      - 2 段階オクルージョン : 半透明は前段で描かず、後段で不透明の後にまとめて描く (重ねる順番を守るため)
      - マテリアルはインスタンスごと (DrawData) に持つので、同じメッシュならマテリアルが違ってもインスタンシングできる
      - インスタンシングしない時も同じ処理 (まとめる数 = 1) にして、別の関数 (writeDrawsDirect) を無くした
  - Renderer   : 1 つのモデルの全サブメッシュで RHI のオブジェクト (ワールド行列) を 1 個共有する
                 (以前はサブメッシュごとに作っていて、動かすたびにサブメッシュの数だけ書いていた)

■ 計測結果 (RTX 2070 / Release / 1280x720)
  見本のシーン (箱 + 岩 4 + PMX 1、29 材質 / 約 11 万頂点) : 34 描画 / 43 インスタンス、約 1040 FPS、GPU 0.114 ms
  負荷テスト (以前と比較)
                                  映った数 / 描画数     GPU (今回)    GPU (以前)
    --stress 10000                 20002 / 1252         0.245 ms     0.242 ms
    --stress 10000 --view ground    1010 / 252          0.111 ms     0.114 ms
  ※途中、不透明のピクセルシェーダーにも clip を入れていた時は 0.255 ms (early-Z が効かなくなるため)。
    半透明だけに分けて元に戻した

■ 確認したこと
  - D3D12 デバッグレイヤーのエラー・警告 0 : 見本のシーン (通常 / --draw direct / --culling off / --occlusion off /
    --instancing off)、負荷テスト
  - 画面 : 箱 (草 / 砂利)、岩 4 個 (拡張子違いのテクスチャも付く)、PMX のキャラクター (顔 / 目 / 髪 / 服 / 靴にテクスチャ。
    髪や裾の半透明が重なる) が一緒に描かれる。キャラクターを回しても崩れない
  - PMX の材質を一覧にして確認 : 29 材質すべてにテクスチャがある。不透明度 0 の材質 (5〜9 : 表情の切り替え用) は描かれない

■ 注意 / 次の課題
  - 肌 (skin / face) が白っぽいのは、まだライティングが無いため (MMD はトゥーン / 環境光で色が付く)。E3 の描画パスで入れる
  - 半透明は DrawItem の順 (= 材質の順) に描く。奥から順に並べ替えてはいない (キャラクター 1 体なら MMD と同じ見た目)
  - PMX の両面フラグは読んでいるが、まだ全部カリングなし (今の PSO は両面描画)
  - ログで日本語のパスが文字化けする (表示だけ。読み込みは正しく行われている)
