 日付   : 2026-11-04

■ 概要
  - Transform に親 (Parent) を持たせた。Position / Rotation / Scale は親から見た値 (ローカル)、
    ワールドの値は WorldPosition / WorldRotation / WorldScale。親が無ければ ローカル = ワールド (今までのコードはそのまま動く)
    以前は親子が無く、Position などがそのままワールドの値だった
  - 描画 / 物理 (コライダー・剛体・ジョイント) / ライト / カメラ / パーティクル / 確認用の線 は、ワールドの値を使う
  - エンティティの有効 / 無効 (Unity の SetActive / activeInHierarchy と同じ)。
    自分か親のどれかが無効なら無効で、描画 / 物理 / ライト / カメラ / 音 / パーティクル / ForEach が飛ばす
  - 親子は保存 / 読み込みでも保たれる (Parent は ED1 の仕組みで親の Id として保存される。変更なしで動いた)

■ 作り
  Transform          : Parent (Entity)。WorldPosition (子は行列から) / WorldRotation・WorldScale (子は行列から分けて取り出す)
                       Forward / Right / Up はワールドの向き (以前はローカルの回転から。親が無ければ同じ)
  TransformSystem    : 1. 親の無い物 (一番多い) を以前と同じ速い道で計算 2. 親のある物がいれば、親を先に計算して
                       ワールドの行列 = ローカルの行列 × 親のワールドの行列。親が動けば、ローカルが同じでも子は「変わった」扱い
                       親が消えた子は親の無い物として扱う。輪 (64 段を超える) はそこで止める
                       有効 / 無効 = 自分の EntityInfo.Active かつ 親が有効 (EntityInfo を持つ物だけ計算する)
  World              : IsActive / SetActive / ActivityVersion。ForEach は無効な物を飛ばす
  Hierarchy          : SetParent (ワールドの値を保つ / 輪は拒む) / GetChildren / DestroyWithChildren / GetWorldMatrix / IsAncestor
  RenderSyncSystem   : 無効になった物の描画オブジェクトを消し、有効に戻ると作り直す (有効 / 無効が変わった時だけ見る)
  CollisionSystem    : 無効な物は体を消す (戻ると作り直す。繋いだジョイントも作り直される)。体にはワールドの値を送る
                       剛体の子 : 物理の位置 (ワールド) を、親から見た値に直して Transform に書く。
                                  親が動くと子は付いて動く (瞬間移動。Unity と同じ)
  Engine             : 剛体が位置を書いた後、親子がある時だけ子のワールドの行列を計算し直す / Quit()
  MeshRenderer       : IsCreated (描画オブジェクトがあるか)
  見本               : Showcase に親子の見本 (回る台 → 子の箱 → 周りを回る孫の箱 (コライダー付き))

■ 確認中に見つけて直した物
  1. 剛体の子が落ちない : 物理が書いたワールドの値と、次のフレームに親から計算し直した値が浮動小数の誤差で違い、
     毎フレーム「動かされた」(瞬間移動) になっていた → 親がある時は 0.1 mm / ごく小さな回転の差は同じ位置とみなす
  2. 性能 : 動かない 1 万個 (--stress 10000) の C# の更新が develop の 0.07 ms から 0.19〜0.24 ms に増えた
     - 全部の物に有効 / 無効の計算と印の書き込みをしていた → 親の無い物は以前と同じ道、有効 / 無効は EntityInfo を持つ物だけ (→ 0.11)
     - Transform にワールドの値の置き場 (40 byte) を足していた → やめて、子だけ行列から取り出す (→ 0.09)
     - Parent が HasMatrix と別のキャッシュの行にあった → 隣に並べた (→ 0.083〜0.090)
     同じ PC で develop と並べて測った結果 : 0.068〜0.078 → 0.083〜0.090 ms (1 個あたり約 1.5 ns 増。親子の判定の分)

■ 確認
  親子のテスト (--hierarchy-test。フレームを進めて確かめる。Release / Debug とも 18 項目すべて OK)
    子 / 孫 (3 段) のワールドの位置 = ローカルの行列を親から掛けた物 / 描画へ送る行列も同じ / ワールドの大きさ /
    Hierarchy.GetWorldMatrix / 子の一覧 / SetParent でワールドの値が変わらない / 輪になる親子は拒む /
    親を動かすと子が付いて動く / 付け替えた物が新しい親に付いて動く /
    親を無効にすると子・孫も無効 / 無効な物の描画オブジェクトが消える / 体が消える / ForEach が飛ばす / 有効に戻すと全部戻る /
    回した親の下の剛体の箱がワールドで床に落ちる (y = 0.4999) / Transform のワールドの値 = 物理の位置 / ローカル = 親の逆 × ワールド /
    保存 → 読み込みで親子が保たれる
  保存 / 読み込みのテスト (--serialize-test) : 見本 / 物理 / パーティクルのシーンで全部 OK (Release / Debug)
  見た目 : 見本のシーンで、回る台と子の箱が一緒に回り、孫の箱がコライダーの線と一緒に周りを回る (ゲームの窓だけを撮った)
  Debug (D3D12 デバッグレイヤー有効) で D3D12 のエラー / 警告 0 : 見本のシーン、物理のシーン、親子のテスト
  計測 (Release) : 衝突判定だけ 1 万個 C# の合計 1.54〜1.57 ms / 5% 0.52〜0.68 ms (起動ごとの揺れの中)、
                   物理 1,000 個 (眠った後) 0.08 ms / 刻み

■ 制限 / 次 (ED3)
  - 親子の中で回転と拡大が混ざると (親を回した後に子を縦長にするなど)、WorldScale / WorldRotation は歪みを無視した値になる
    (描画の行列は正しい。物理の形は歪められないので近い形になる)
  - 動いている剛体 (Dynamic) の子は、親が動くと付いて瞬間移動する (Unity と同じ。物理で付いて行かせるならジョイント)
  - World.DestroyEntity だけでは子は消えず、親の無い物になる (子も消すなら Hierarchy.DestroyWithChildren)
  - 次は ED3 : エディターの枠 (ImGui.NET を C# から。シーンビュー / 階層 / インスペクター / コンソール / プロファイラー)。
    ImGui.NET の取得 (NuGet。ダウンロード) の許可が要る
