■ 概要
  - シャドーマップを 1〜4 段のカスケードにした (Depth32 の配列 = Texture2DArray。1 段に 1 枚)
    近い段ほど細かいので、近くはくっきり、遠く (既定 60) まで影が出る
  - 段の境目をなめらかにつなぐ (CascadeBlend 10%)。F12 で段を色分けして確認できる (赤 → 緑 → 青 → 黄)
  - 効率化を 6 つ検討し、計測で 2 つを採用 (全段で 1 回のカリング / 遠い段の間引き)。下の表
  - 既定 : 3 段 / 2048 / 距離 60 / 1 回のカリング / 間引きあり
    Graphics.Shadows : CascadeCount / SplitLambda / CascadeBlend / ShowCascades / UnionCulling / ThrottleFarCascades
    コマンドライン : --shadow-cascades N / --shadow-union on|off / --shadow-throttle on|off / --shadow-show on

■ 仕組み
  RHI
    - 深度のレンダーターゲットに配列 (RenderTargetDesc.ArraySize。最大 4)。DSV は 1 枚ずつ、SRV は配列
      描画先にする時は SetRenderTargets の Arg0 (C# の depthSlice) で何枚目かを選ぶ
    - Buffer::computeShadowViews : カメラの視錐台を奥行きで分け (対数と均等の混ぜ合わせ : SplitLambda)、段ごとに S1 と同じ方法
      (囲む球 + テクセル単位の丸め) で行列を作る。手前の段は境目をつなぐ分だけ奥へ広げる
    - 全段を囲む箱 (ライトの回転の空間の AABB) も作る。1 回のカリングに使う
    - FrozenMask の段は行列を作り直さない (間引き : 前に描いた時の行列のまま読む)
  シェーダー
    - 奥行きで段を選ぶ → PCF (S1 と同じ) → 境目の幅では手前の段とも読んで混ぜる
    - 選んだ段の外だった時 (間引いた段がカメラの移動で足りなくなった時) は、次の段で読む
    - シャドーマップの SRV は Texture2DArray<float> (t0, space3。S1 は Texture2D<float>)
  C# (ShadowPass)
    - 段ごとに「配列の c 枚目を消す → 視点 c + 1 で不透明 / 半透明を描く」
    - 間引き : 3 段目は 2 フレームに 1 回、4 段目は 4 フレームに 1 回 (同じフレームに重ならないようにずらす)
      作り直した直後は全段を描く

■ 効率化の検討 (ロードマップの a〜f)
  RTX 2070 / Release / 1280x720 / AA なし / SSAO あり / GPU 時間 (ms)。2 回計測。影なし 0.276〜0.280
  a. 段の数 (段ごとのカリング・間引きなし・2048)
       1 段 0.377 / 0.381   2 段 0.459 / 0.462   3 段 0.626 / 0.622   4 段 0.736 / 0.730
       1 段 1 枚ずつ +0.09〜0.16。見本のシーンでは、どの段にもキャラクター (18 万三角形の大半) が入るため
       見た目 : 1 段で距離 60 にすると影がほとんど消える (1 texel が粗い)。3 段と 4 段はこのシーンではほぼ同じ
     解像度 (4 段) : 2048 0.736 → 1024 0.628〜0.651。1 回のカリング + 間引きでは 2048 0.572〜0.630 → 1024 0.456
  b. カリング : 段ごと vs 全段を囲む箱で 1 回  → 1 回を採用
       見本 4 段 : 0.736 → 0.649〜0.652
       負荷テスト 2 万個 4 段 : inside 0.807〜0.813 → 0.712〜0.768 / ground 0.750〜0.753 → 0.657〜0.701 /
                                orbit 0.627〜0.649 → 0.573〜0.617
       物が多い場面でも 1 回の方が速かった。段ごとにカリングすると、前の段の描画 (ExecuteIndirect) が
       Culled バッファを読み終わるまで次の段のカリングが書き込めず、GPU が待つ (1 回 約 0.025〜0.03 ms)
       (段ごとに別のバッファへ先にまとめてカリングすれば待ちは消える。今は 1 回で十分なので見送り)
  c. 全段を 1 回の描画で (インスタンスで段を振り分け、SV_RenderTargetArrayIndex) → 見送り
       重いのは「三角形 × 段の数」の処理で、1 回にまとめても三角形の数は減らない。命令の記録 (CPU) は 0.06〜0.07 ms で、
       段の数でほぼ増えない (1 段 0.059 / 4 段 0.071)。カリングの待ちは b で解消済み
  d. 遠い段の描き直しの間引き → 採用
       4 段 : 0.736 → 0.624〜0.647 / 1 回のカリングと合わせて 0.572〜0.630 / 3 段 + 1 回のカリング : 0.562〜0.567 → 0.495
       代わりに、動く物の遠くの影が 2〜4 フレームに 1 回の更新になる (近い 2 段は毎フレーム)
  e. 動かない物のキャッシュ → 見送り
       見本のシーンでは影を描く三角形の約 95% がキャラクター (動く) で、動かない物 (地面・箱・岩) を
       キャッシュしても減る量が小さい。背景の多い場面を作った時にもう一度検討する
  f. 画面の影を先に 1 枚に作る (スクリーンスペースのシャドーマスク) → 見送り
       影を読む処理 (PCF) は S1 の計測で Forward +0.017 / Deferred +0.024 ms。マスクを作る全画面のパス
       (深度を読んで書く) の方が重くなる見込み。ライトが 1 つの間は今の形がよい
  試して戻したこと
    - 影専用の頂点シェーダー (位置だけ / 半透明は UV と α だけ) : 4 段 0.733 → 0.720〜0.737。変わらないので戻した
    - 半透明のアルファテストを外す (早期 Z が効くか) : 4 段 0.738 → 0.738。変わらない (戻した)

■ 既定の設定での計測 (3 段 / 2048 / 1 回のカリング / 間引き)
                                   影なし            影あり            差
    AA なし                        0.280 / 0.280    0.491 / 0.494    +0.21
    FXAA (既定の設定)              0.343 / 0.340    0.596 / 0.656    +0.25〜0.31 (ばらつきが大きい)
    Deferred / AA なし             0.311 / 0.311    0.579 / 0.595    +0.27
  S1 (1 段・距離 30) は +0.10 だった。距離を 60 にして近くも細かくした分、重い。
  軽くしたい時 : 段を 2 (0.44) / 解像度 1024 (4 段で 0.456) / 距離を短く

■ MSAA 4x + SSAO の時だけ影が重い件 (S1 からの持ち越し)
  1 段 : MSAA 4x + SSAO なし +0.11 (0.297 → 0.406〜0.409) / MSAA 4x + SSAO +0.145 (0.427〜0.440 → 0.576〜0.583) /
         AA なし + SSAO +0.10。段の数とは関係なく、MSAA と SSAO が両方の時だけ +0.04 多い。原因は特定できていない
  (影を読む処理は 1 ピクセル 1 回で MSAA でも同じ。シャドーマップを描く処理も同じ。GPU の並び方の違いと見ている)

■ 確認
  - Debug (D3D12 デバッグレイヤー有効) で D3D12 のエラー / 警告 0
      Forward + FXAA / Deferred / MSAA 4x、4 段 + 段ごとのカリング + 間引きなし、1 段、
      負荷テスト (orbit = カメラが動く + 間引き / inside + Deferred + MSAA 8x)、リサイズ、F11 / F12 / F2 / F3 / F6 の切り替え
  - F12 (段の色分け) : 近くが赤 (1 段目)、その先が緑 (2 段目)。境目はなめらか
  - 見た目 : 1 段 (距離 60) では影がほぼ消えていた箱・キャラクターの影が、3 段 / 4 段ではくっきり出る

■ 制限 / 次
  - 点光源の影は無い (S3 の候補)
  - 間引いた段は、速く動く物の遠くの影が少し遅れる (止めたい時は ThrottleFarCascades = false)
