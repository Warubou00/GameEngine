■ 依頼と対応 (設計の P3。Unity 6 の Render Graph Viewer に当たる窓)
1. Render Graph Viewer の窓 … 対応 (View > Analysis > Render Graph Viewer)
   - 格子 : 横 = 描画パス (実行した順。直接リソースを使ったパスだけ)、縦 = リソース
     セル : 赤 = 書く / 緑 = 読む / 黄 = 読み書き / C = 消す / R = MSAA の解決 / 斜線 = 深度 (書く・比べる) /
            輪郭の緑 = 命令に書いていない読み (影のシャドーマップ) / 橙の三角 = 遷移バリア / 灰色の帯 = 寿命 (最初 〜 最後に使ったパス)
   - 1 行目 : 一番外のパス (Camera 0 / Finish (debug lines) / UI) の名前。2 行目 : パスの番号 (上に乗ると親をたどった名前)
     番号が青 = 一つ前のパスと描画先 (色 + 深度) が同じ = まとめられる候補 (Unity の Native Render Pass の合体に当たる)
   - 右の Resource : 形式 / 大きさ / MSAA / 配列 / GPU のメモリ / 寿命 / 中身の絵 (フレームの終わり。色だけ) /
                     使われ方とバリア (例 : PIXEL_SHADER_RESOURCE -> RENDER_TARGET) の一覧 (実行した順)
     Pass : 親のパス / 時間 (P2 の値) / 子のパス / 読み書きしたリソースとバリア
     Passes : パスの一覧 (入れ子) / Warnings : 書いたのに読まれない、書く前に読む (前のフレームの中身)
   - Live (毎フレーム更新) / Capture (今のフレームで止める) / Hide unused / Barriers / 名前で絞る

2. GPU テクスチャがどの状態で使われているか … 対応
   - makeTransitionBarrier を通る遷移バリアを、その時のパスと一緒に記録 (D3D12_RESOURCE_STATES の名前で出す)
   - MSAA の写し (Resolved) に掛かったバリアは "(resolved copy)"

3. Memory の窓のレンダーターゲットごとの GPU のメモリ … 対応 (P1 で「予定」と出していた所)
   - GetResourceAllocationInfo (MSAA の写しも含む)。大きさ / 名前の順に並べ替え。合計

■ 記録の仕組み (C++ : CommandContext_Passes.cpp)
- RenderGraphCapture.Capture (= Renderer_SetRenderGraphCapture) の間だけ。Render Graph Viewer か Memory の窓が開いている間
- 記録する物 : 描画先への描画 (DrawScene / DrawFullscreen / DrawCustom / DrawParticles / DrawPreview)、消す、全画面シェーダーの入力、
  深度 (不透明 / 影 = 書く、半透明 = 比べる、SH3 = テクスチャとして読む)、MSAA の色の解決 / 深度の解決、影のシャドーマップ (命令に無い読み)、
  パーティクルの深度の読み、遷移バリア (レンダーターゲット / シーンの深度 / MSAA の深度 / 画面)
- 記録しない物 : バッファ (GPU カリング / スキニング / パーティクル) のバリア、ディファードのライティングが読む影 (全画面シェーダーごとには分からない)
- エディターでは画面の代わりにシーンの絵 ("Scene View (editor)") に描いているので、BackBuffer への描画はそちらに付く
- パスの外の読み書きが出ないように、C++ の後片付け / 確認用の線を "Finish (debug lines)" のパスで囲んだ
- 中身の絵 : Renderer_SetDebugReadTarget の物を UI の前に PIXEL_SHADER_RESOURCE にする (深度 / 配列は ImGui で読めないので出さない)
- エンジンは自動のバリア / パスの削除 / メモリの使い回しをしないので、この窓は「実際に実行した命令の列」を見せる物
