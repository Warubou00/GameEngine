■ 速さ (Release、RTX 2070、エディター、軽いシーン (clouds) から showcase を初めて読む = アセットがまだ無い状態)
- 同期 : 一番長いフレーム 452〜454 ms (その間は画面が止まる)
- 非同期 : 一番長いフレーム 354〜1356 ms (5 回)、中央値 2.5〜23 ms
  一番長いフレームはどれも 1 つの物 'Entity 9' (Tomimi.pmx を持つ MeshRenderer) の C++ の Renderer_LoadModel
  (PMX の解析 + テクスチャ + GPU への転送を 1 回で行う。メインのスレッドだけ)。1 つの物の中では止められないので、予算では分けられない
  → ほかの物 (と前のシーン / ロード画面) は毎フレーム動くが、大きなモデルの所で 1 回止まる。直すのは S4 (C++ の読み込みを CPU の解析 = 別のスレッド
    と GPU への転送 = メインに分ける)。非同期の方が長い回があるのは、読み込みが前のシーンの描画と重なるためと思われる (確かめていない)
- 先に読む (prefetch) : 8.0 MB を別のスレッドで読んでいる (ファイルを開く時間は減るはずだが、上の 1 回の長さはほぼ C++ の処理)

■ 気を付けた所
- 非同期の Single を有効にする時の「残す物が無ければ World.Clear」の近道は使わない (読み終わったシーンの物まで消えるため)
- ゲームのコードの中から LoadSceneAsync を呼んでよい (World を触るのはフレームの頭から)
- エディターの停止 / World.Clear で読み込み中の物も消えるので、その Operation は次のフレームで取りやめになる
