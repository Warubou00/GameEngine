■ 依頼と対応 (設計の P2)
1. 描画パスの区切り … 対応
   - C# : RenderCommandBuffer.BeginPass("名前") / EndPass()。using (cmd.BeginPass("Bloom")) { ... } で囲む。入れ子にできる
   - 命令 : RenderCommandType::BeginPass (11。Arg0 = 名前の番号) / EndPass (12)。描画の結果には影響しない
   - 名前の番号 : Renderer_RegisterPassName (C# が名前ごとに 1 回だけ聞いて覚える)
   - 閉じ忘れは C++ が ExecuteRenderCommands の終わりで閉じる
   - 組み込みのパイプラインに区切りを入れた :
       Camera N / Clear BackBuffer / Shadows (Cascade N) / Clear + Sky / Skybox / Opaque / Particles Update / SSAO (SSAO Blur) /
       Transparent / Particles / Tonemap / FXAA / SSAO Show / GBuffer / Deferred Lighting / Forward (custom + transparent) / Preview
     C++ の中 : Skinning (compute) / UI (ImGui / game UI)

2. パスごとの GPU の時間 … 対応
   - GpuTimer のタイムスタンプの枠 : 1 フレーム 10 → 10 + 256 (パスの分 = 10 番から 128 パス)。読み戻しは別の範囲 (ResolveRange / ReadTicks)
     (以前は フレーム / シーン / UI / パーティクル / スキニングの 10 個に決まっていて、シーンの中の内訳が分からなかった)
   - タイムスタンプは Profiler.PassTimingEnabled の間だけ書く (エディターの GPU Usage の窓が開いている間)。FRAME_COUNT フレーム後に読む
   - 結果 : Profiler.ReadPassTimings → PassTimingSample (Name / Depth / GpuMilliseconds (計っていない時は -1) / CpuMilliseconds)

3. パスごとの CPU の時間 (C++ が命令を積んだ時間) … 対応 (毎フレーム)

4. PIX / RenderDoc のイベント … 対応 (毎フレーム)
   - ID3D12GraphicsCommandList::BeginEvent / EndEvent (Metadata 0 = UTF-16 の文字列。WinPixEventRuntime なしの PIXBeginEvent と同じ形)

5. RenderTexture の名前 … 対応
   - RenderTexture.Create(..., name:) / CreateFixed(..., name:) / Name プロパティ。C++ は D3D12 の SetName (MSAA の写しは "名前 (resolved)")
     画面の大きさが変わって作り直しても付け直す
   - 組み込みの物 : HDR (Forward / Deferred) / Ambient (Forward SSAO) / LDR (FXAA input) / Particles (half res) / GBuffer Albedo / Normal / Material /
     SSAO / SSAO Blur / Shadow Map / Camera N Target / Preview Color / Depth。BackBuffer / SceneDepth は C# の名前だけ

6. エディターの窓 … 対応
   - GPU Usage : 「Render passes」の表 (入れ子は字下げ。GPU ms / % GPU (一番外のパスの合計に対して) / CPU ms)。
     行をクリックするとそのパスの GPU の時間のグラフ (同じ名前のパスはカメラが複数でも足す。右クリックで消す)
   - CPU Usage : 「Render passes (C++ record)」の表

■ 確認
- エディターの自動の確認 (--editor-test、Release) : pass 412 / fail 0 (P1 の 405 + P2 の 7)
  書き出したゲーム (Player) とエディターの再生が同じ動きの確認も含む (Player も新しい命令を通る)
- プロファイラーだけ (--editor-test-section profiler) : Release 22 / 22 を 2 回、Debug 22 / 22
  - パスが順番と入れ子で出る (Skinning (compute), Camera 0, Shadows, Cascade 0..., Clear + Sky, Skybox, Opaque, ...、UI)
  - どのパスにも GPU / CPU の時間がある (Opaque 0.158 ms。一番外の合計 0.892 ms ≒ フレームの GPU 0.894 ms)
  - 影の段が Shadows の中に入れ子 / Deferred のパス (GBuffer / Deferred Lighting / Forward (custom + transparent))
  - RenderTexture の名前 / GPU Usage を閉じると GPU は -1 で CPU は出る
- Debug ビルド (D3D12 のデバッグレイヤー。メッセージは Logger に出る設定) : D3D12 の ERROR / WARNING は 0 件
- 見た目 : 5 つの窓を並べて撮り、GPU Usage の Render passes の表 (Shadows 26.5% / Cascade 0 18.7% …) を確かめた
- 見ていない物 : PIX / RenderDoc で実際にイベントと RT の名前が出るか (ツールが入っていないため。D3D12 の API の呼び方だけ)

■ 性能 (Release、RTX 2070、エディター 1600x900 の showcase、300 フレームの平均を 切 / 入 / 切 / 入、2 回)
- パスのタイムスタンプ 切 : GPU 合計 0.665 / 0.622 ms、記録 (C++) 0.202 / 0.220 ms   (2 回目 : 0.676 / 0.626、0.179 / 0.181)
  パスのタイムスタンプ 入 : GPU 合計 0.630 / 0.633 ms、記録 (C++) 0.229 / 0.216 ms   (2 回目 : 0.631 / 0.637、0.186 / 0.184)
  → 差は揺れの範囲 (最初の「切」は温まる前で高め)。タイムスタンプ 32 個 / フレームでは測れるほどの差は無かった
- PIX のイベントと CPU の時刻 (パスごとに steady_clock 2 回) は毎フレーム。上の「切」にも含まれる (別には測っていない)
- 一番外のパスの GPU の合計 0.892 ms ≒ フレームの GPU 合計 0.894 ms (パスの時間がフレームと合っている)
