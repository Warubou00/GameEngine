■ 依頼と対応 (設計の P4。Unity の Frame Debugger に当たる窓)
1. 描画結果をイベントごとに確認できる窓 … 対応 (View > Analysis > Frame Debugger)
   - Enable : 1 フレームの描画をイベントに分ける
       消す (色 / 深度) / シーンの描画 1 回 (メッシュ × マテリアル。インスタンシングならまとめた数) / 全画面 /
       パーティクルの更新・描画 / 自分のシェーダー (SH2) の 1 個 / プレビューの窓
   - 左 : 描画パスごと (Camera 0 / Opaque など、親をたどった名前の見出し) のイベントの一覧
     スライダー / ◀ ▶ / 窓にフォーカスがある時の ← → (↑ ↓) で 1 つずつ動かす / Refresh で一覧を取り直す
   - 右 : 止めた時の描画先の絵
       描画先の選択 (RT 0〜3 = MRT の何枚目 / Depth)、R G B A (1 つだけなら白黒)、Levels (HDR の明るい所 / 深度の差を広げる)
     詳細 : パス / 描画先 / 深度 / シーンのパス・列・描き方 (不透明 / 半透明 / 両面) / 視点 (カメラ / 影の段) /
            インデックス・三角形 / インスタンスの数 / 物 (ボタンで Hierarchy で選ぶ) / マテリアル /
            全画面 : シェーダーの名前 (ファイル : 入口) / ブレンド / 入力の名前 / g_Params の値 / 消す色・深度の値
   - Enable の間は再生中ならゲームを一時停止する (Disable / 窓を閉じると戻す)

■ 仕組み (C++ : CommandContext_FrameDebug.cpp、シェーダー : frameDebug.shader)
- 毎フレーム同じフレームを描き直し、StopEvent のイベントまで描いたら、その時の描画先を PSFrameDebugView で確認用の絵
  ("Frame Debugger View"、RGBA8) へ写して、残りの描画を飛ばす (パスの区切りと UI / 後片付けは続ける)
- Enable の間 : ExecuteIndirect / GPU カリング / オクルージョンを使わず 1 個ずつ描く (描画ごとに止めるため)
  影の遠い段の間引き (ThrottleFarCascades) もしない (フレームごとにイベントの並びが変わると同じ所で止められないため。
  確認の途中で、一覧のフレームと止めたフレームでイベントの番号がずれていたので足した)
- イベントの一覧は止めずに描いたフレーム (StopEvent = -1) で取る (止めたフレームは止めた所までしか数えない)
- 描画 → 物 : 描画の引数 → 最初の DrawItem (インスタンシングでまとめた時は最初の 1 つ) → Renderer の描画オブジェクト → MeshRenderer.Handle
- 写せない物 : 画面 (Player のバックバッファ) / 深度の配列 (シャドーマップ)。窓に理由を出す
- 止めている間、シーンビューは最後まで描いたフレームの絵のまま (止めた所から後は描かないので)
